# 工作台v4前端：主控对话、执行监控与成果验收

日期：2026-10-15。配套 [新默认工作流](conversation-workbench-v4.md)。作为自动开发tab内容重做，不复制应用全局侧栏、中央聊天壳、左右通用辅助栏或状态栏。生产目标为Avalonia；HTML只是可评审样稿，不是新增Web运行时。

## 入口与层次

自动开发tab默认进入“总览”。当前项目自动关联工作台/宿主，首次无项目给选择项目入口，不要求用户选择SQLite文件。项目切换保留各自草稿/筛选/未决输入，过期输入保留但不能作用到新版本。

顶部固定项目名称、运行状态、模式“自动开发”、后台连接状态。主操作为暂停新任务/继续，紧急停止另放有明确范围的按钮；已完成显示“查看交付”，不是仍显示暂停。模式在委托设置内保留人工/半自动，不作为每次开工必填。

tab内二级页签：总览、执行线程、成果与验收、活动记录。右侧详情是tab自己的可收起抽屉，不绑定/覆盖全局辅助栏。窄于1000DIP时改底部详情，800×640仅一列+折叠上下文，不能横向溢出到整个应用。

## A. 总览：默认工作界面

```text
项目名   开发中 · 自动开发             后台已连接  [暂停新任务] [停止项目…]
总览 | 执行线程 | 成果与验收 | 活动记录                         [委托与预算]
────────────────────────────────────────────────────────────────────
当前：审核资料库交付后，继续附件接线             需要你决定 1 · 工作中 2
┌ 主控对话 ─────────────────────────────┐ ┌ 执行概况 ──────────────┐
│ 你的目标 / 主控解释 / 决定与成果卡      │ │ A 浏览器 · 工作中      │
│ 计划摘要可展开，不倾倒日志             │ │ B 手机端 · 等待审批    │
│ 消息可见“已保存/已送达/处理中”         │ │ 下一步：审批后继续     │
│                                       │ │ [查看线程与依赖]        │
│ [补充要求…] [发送]                     │ ├ 需要你决定 ───────────┤
│ 自动模式下自行规划并在委托范围内推进   │ │ 问题、影响、明确选项    │
└───────────────────────────────────────┘ └────────────────────────┘
最近成果：已整合 2 · 待审核 1 · 验证待补 1     最后有效进展 3分钟前
```

“当前”条是宿主结构化下一步摘要，不由前端猜测。主控消息显示类型：用户目标、规划说明、派工、问题、审核结论、整合结果、阶段交付；正常路径不让用户逐项批准。

输入框发送要求默认送主控；线程详情输入默认该线程，显著展示收件人。忙时显示排队和收件状态，不能用旋转图标假装已读。修改要求产生目标版本变更并展示影响，不仅追加一条谁也没处理的聊天。

需要用户决定的卡只含真正保留事项，给事实/影响/建议/选项及预算变化。普通方法命名、内部实现、既定范围内重试不占人类收件箱；危险工具审批单独标明，不能被“自动开发”模式隐式免除。

## B. 执行线程：控制实际工作

上方切换“列表/依赖图”，列表默认，图保留线程节点及内部任务/部分端口，默认只展开活跃/阻塞项，可展开全部。卡片显示任务/线程标题、真实harness/模型/强度、阶段、工作树、起点/当前SHA、最后事件/最后有效进展、停顿原因、预计下一动作；无用量时显示未知。

点击卡片打开详情：会话、任务与依赖、改动与证据、通信、运行资源五项。允许查看真实执行输出，不让执行者假最终文本覆盖真实运行状态。

线程操作按能力提供：补充指令、请求停止、原会话修复、查看工作树、打开差异。忙时补充输入明确为活动steering或排队待下轮，适配不支持则不可伪造成功。停止是请求中→已确认停止/停止结果未知，不立即把线程涂成完成。不在每张卡默认放删除/重建/换模型。

通信显示来源/目标、类型、关联任务版本和时间，依次显示已保存/已投递/已接收/已处理；“投递结果未知”提供核对原回执，禁止盲目重发按钮。支持按失败/阻塞/交付筛选，不把所有token增量当跨线程消息。

## C. 成果与验收：控制交付真实性

按任务交付部分展示已提交、已接受、已整合、已验证、未验收。每项提供实际提交/目标版本、文件范围、验证passed/failed/notRun、证据入口、接线需求和审核结论。旧版本标过期，保留历史，不可用旧证据批准新版本。

自动模式下主控正常审核/集成在此实时展示，不要求用户手点每一张；用户可提出修正、人工接管或查看冲突。部分返工只选择具体部分和问题，其他已接受部分不回滚。

最终验收面板按用户目标列覆盖项、验证状态与缺口，绑定准确候选SHA。只有真实终验通过显示“项目已完成”；发布/推送仍是另一个获授权动作，不将“完成”按钮当发布。

## D. 活动记录：解释为什么停、为什么继续

时间线默认看派工、交付、决定、整合、阻塞、恢复、需求变更。区分业务进展和宿主健康：token正在生成/进程活着不等于有有效进展。每条可定位任务/线程/版本，附操作者与来源；支持查看原始证据但默认不露内部JSON。

页面给最后对账时间、待投递/待处理条数、补漏是否开启、下次本地检查时间、宿主断连提示。无网络/宿主离线保持最后快照并标“截至…”，禁用不安全动作；重连按游标补齐，不能用旧画面当实时。

## E. 委托、预算和后台设置

项目设置抽屉：目标与验收、允许范围、自动审核/集成、并发/模型策略、预算边界、周期本地补漏。默认自动已选，输入目标并点击开始是一次委托，不增加十个批准表单；越权事项另外处理。

全局后台设置仍放设置页：关闭窗口继续后台、登录自启、后台状态/停止入口。用户选择退出时说明“只关闭窗口/暂停并关闭/停止后台”，已授权默认行为可记住。原生内核/插件不就绪时给真实安装或配置入口，不展示假运行。

## 控制语义

| 操作 | 精确效果 |
| --- | --- |
| 提交目标/补充要求 | 创建或更新目标版本，产生一条主控待处理事件，返回消息回执 |
| 暂停新任务 | 不再新派，现有运行继续；待审成果仍落盘，下一决策按暂停策略等待 |
| 继续 | 按当前状态对账后恢复，不重放旧派单 |
| 停止线程 | 请求取消选定run，等实际终态/子写入者停止，不等同项目暂停 |
| 停止项目 | 进入Stopping，停止该项目M及worker/排队副作用后Paused；不停止别的项目 |
| 人工接管 | 改决策所有者，保在途事实，用户选择是否另行暂停/停止 |
| 核对消息 | 查询原messageId/commandId及结果，不重新执行发送或工具 |
| 关闭窗口 | 按后台偏好断开GUI；不能取消所有运行或新建宿主 |
| 完成验收 | 绑定目标/候选快照的真实决定；不覆盖旧版本或自动发布 |

## 数据投影（设计契约，不是已存在字段）

ProjectView包含projectId/goalVersion/mode/delegation/status/reason/nextAction/hostObservation。ThreadView包含threadId/taskParts/backend/model/effort/worktree/runState/lastProgress/availableActions。MessageView包含messageId/correlation/run/revision/deliveryState/processingState。DeliveryView包含partId/revision/head/settled/review/integration/verification。所有动作带commandId与expectedVersion，返回明确accepted/rejected/unknown。

前端不解析自然语言猜完成/自动重试，不直接执行shell或改数据库。后端提供动作可用性与原因；没有完整观测时明确unknown。变化通知更新绑定对象，重放事件不产生新命令。界面虚拟化长列表，日志限量，键盘焦点/草稿/滚动位置保留。

## 视觉与行为验收

沿现有UniGetUI/Windows设置式色调与App动态资源：亮暗、语义状态、克制强调色。新组件复用现有Button/TextBox/ComboBox/List/Dock样式，不另添全屏外壳，不用绿色表示所有过程完成。图标用现有语义资源，图标按钮有名称，所有状态有文本。

原生需验证800×640/1100×800、125%/150%DPI、中文IME输入草稿、键盘/返回、弹出层、线程切换、事件突发、脱机重连、部分返工、停止未知、迁移旧项目。样稿只验证信息布局与点击关系，不能替代原生或真实执行验收。
