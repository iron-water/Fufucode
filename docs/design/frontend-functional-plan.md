# Fufucode 前端功能拆解与规划

日期：2026-10-05。状态：待用户确认的产品方案，不代表已实现或已验收。

配套交互示意：`../frontend-prototype/index.html`。它只演示布局、入口和状态，不执行 Pi、Shell、浏览器导航、文件写入或云端操作。

## 1. 产品范围与定案边界

Fufucode 是 Windows 优先、基于官方 Pi RPC 的桌面 coding agent。中央对话负责下达任务与阅读结果，周边功能页面负责导航、检视和辅助操作。目标是可长期使用的工作台，而不是把多个固定抽屉拼在聊天窗口周围。

本轮用户已经明确的要求：

- 修改后可以重新启动开发版查看结果，不必每次制作安装包；热重载不是前置条件。
- 左、右、底三个边栏/停靠区的位置用途可自定义，功能页面可自由分配。
- 必须提供统一快速跳转、浏览器、可用终端、广泛文件预览、侧栏提问。
- 主会话需要可靠 Markdown 与 `$$...$$` 数学公式；Mermaid 是期望增加的能力。
- 需要消息操作、会话顶部快捷入口、变更摘要卡和会话内跳转。
- 先确认基础功能与页面结构，再开展产品实现。

下文的默认布局、细节、优先级和分期均为建议，尚未获得用户最终确认。旧 `frontend-design-guideline.md` 的固定用途五区设计保留为历史研究；本方案建议改为“中央对话 + 三个通用停靠区 + 独立设置”。除新布局要求外，继续遵循原开发计划的 Pi/Core/App 职责边界。

## 2. 信息架构

| 区域 | 固定责任 | 可变内容 |
|---|---|---|
| 全局标题栏 | 项目、全局搜索/命令、停靠区开关、通知、设置、窗口控制 | 不承载第二套页面导航 |
| 中央主工作面 | 会话头、对话时间线、摘要卡、消息操作、主输入框 | 当前会话、焦点阅读状态；基础版不提供多个中央对话分屏 |
| 左停靠区 | 通用标签宿主 | 任意功能页面 |
| 右停靠区 | 通用标签宿主 | 任意功能页面 |
| 底停靠区 | 通用标签宿主 | 任意功能页面 |
| 独立设置目的地 | 分类设置、保存与返回 | 保留离开前会话和布局，返回时恢复 |

默认摆放建议：左侧“概览 / 文件”，右侧“变更 / 文件预览 / 浏览器 / 侧栏提问”，底部“终端”。中央会话左缘保留可折叠的轮次刻度。它是当前会话的阅读工具，不是另一个全局边栏。

### 2.1 停靠规则（L 系列）

| 编号 | 功能 | 建议基础行为 | 验收条件 |
|---|---|---|---|
| L-01 | 三个通用宿主 | 每区标签条、活动页面、增加页签、关闭页签、收起区域 | 同一页面可迁至任意区，操作后数据与状态不重建丢失 |
| L-02 | 位置自定义 | 标签菜单“移到左/右/底部”，并支持跨区拖动 | 鼠标与菜单均能移动；投放目标明确；取消拖动不改变布局 |
| L-03 | 区内排序 | 拖动标签调整顺序 | 排序与选中项在重启后恢复 |
| L-04 | 尺寸调整 | 拖动分隔条；区域最小尺寸约束 | 不挤没中央输入框；恢复宽窗口后保留用户尺寸 |
| L-05 | 布局保存 | 应用级默认布局，项目级覆盖；提供“恢复默认布局” | 重启、切会话不丢布局；切项目按明确策略恢复 |
| L-06 | 窄窗口 | 不强行显示三栏；侧区采用互斥抽屉，底区按高度折叠 | 页面不越界，抽屉不遮挡可操作输入与关闭入口 |
| L-07 | 页面实例 | 概览与文件树基础版单实例；终端、文件预览、浏览器可多实例 | 同一终端跨区移动不启动新进程；预览标签可固定 |
| L-08 | 关闭语义 | 收起区域不关闭内部任务；关闭正在运行的终端/提问需明确处理 | 不悄悄杀进程，不留下无归属后台任务 |
| L-09 | 恢复能力 | 有效布局迁移；已移除页面从布局中跳过并给出可操作提示 | 损坏配置不会阻止启动，存在恢复默认入口 |

基础版不做浮动独立窗口、任意嵌套分割、第三方插件自定义布局宿主。它们不是实现三位置可配置的必要条件。

## 3. 功能页面目录

所有功能页面都遵循同一宿主协议：稳定页面 ID、标题/图标、页面实例 ID、所属项目/会话、可移动性、关闭前处理、可持久化状态。不再按左/右/底分别写三套页面逻辑。

### 3.1 概览与快速跳转（N 系列，必做）

| 编号 | 功能 | 规划 |
|---|---|---|
| N-01 | 项目与会话一览 | 项目展开/收起、会话分组、搜索、最近访问；显示真实运行/待审批/失败/未读状态 |
| N-02 | 会话管理 | 新建、切换、重命名、归档、删除、打开项目目录；危险操作需明确对象与结果 |
| N-03 | 功能页快速入口 | 一个统一页面目录打开概览、文件、变更、预览、浏览器、终端、提问；设置和扩展为独立目的地 |
| N-04 | 全局命令面板 | 同一动作注册表提供搜索和执行；键盘定位；不可用动作有原因 |
| N-05 | 当前会话目录 | 按用户请求/轮次列出摘要，可定位到消息，显示当前位置 |
| N-06 | 合并重复导航 | 删除重复的图标轨页面导航、左栏导航与对话内全局导航；顶部只保留区域开关与全局动作 |

概览里的一览与命令面板可以是同一动作的两种访问方式，但不能注册两套互相不同的动作与状态。会话刻度只负责“这段对话读到哪里”，项目列表负责“去哪个会话”。

### 3.2 文件浏览（F 系列，必做）

- F-01：项目目录树、按名称过滤、当前文件路径、刷新、显示隐藏文件开关。
- F-02：单击显示文件信息；双击打开可复用预览标签，固定标签后后续文件使用新标签。
- F-03：右键提供预览、复制路径、打开所在目录、作为主会话/侧栏提问上下文；基础版不要求代码编辑器。
- F-04：大目录分页/按需展开，符号链接不无限递归，明确无权限、缺失、加载中和为空。
- F-05：文件树与变更页使用同一预览服务，不能维护两个不一致的支持格式清单。

### 3.3 变更与 Diff（D 系列，必做）

- D-01：工作树 / 会话直接写入两种范围，明确范围与来源，不把 agent 工具写入清单当完整 Git diff。
- D-02：文件列表展示新增/删除/修改/重命名、二进制、冲突；统计由真实数据提供，未知显示未知。
- D-03：点击文件打开逐行 diff；至少支持统一视图，建议提供并排模式、行号、增删高亮、跳到上一/下一处变更。
- D-04：从 diff 切到当前文件预览；缺失文件、删除文件、超大文件和二进制使用不同状态。
- D-05：摘要卡提供文件数与变更状态，点击进入同一变更页面。
- D-06：单文件还原作为后续能力，须验证基线、外部修改与冲突；能力未完成时不显示伪可用按钮。不能仅调用普通写文件冒充安全撤销。

### 3.4 文件预览（P 系列，必做）

“绝大部分文件”按格式矩阵落实；不存在可预览所有二进制的通用渲染器。不支持的格式也必须有清晰降级。

| 格式类别 | 基础版预览 | 后续增强 / 边界 |
|---|---|---|
| 代码、配置、日志、纯文本 | 文本、行号、查找、编码提示、大文件截断/分段 | 常见语言高亮；超大文件虚拟化 |
| Markdown | 渲染 / 源码切换、链接、表格、代码、数学公式、Mermaid | 相对图片/链接按项目解析，远程资源策略明确 |
| HTML | 页面 / 源码切换，通过浏览器宿主打开 | 区分静态预览与可执行 HTML；不声称不执行脚本 |
| 常见图片 | 缩放、适应窗口、原尺寸、尺寸信息 | SVG 按浏览器能力处理；动图遵循渲染器支持 |
| PDF | 页码、缩放、查找，建议复用 WebView2 PDF 能力 | 本机行为需实测，不能只因浏览器支持就标验收 |
| CSV/TSV/JSON | 基础文本预览，建议加表格/结构视图 | 大表格限制、无效数据降级 |
| 音频/视频 | 按系统/WebView2 支持播放，明确不支持编码 | 不是承诺支持所有容器和编解码器 |
| Office 文档 | 文件信息 + 系统应用打开 | 内置排版预览需要专门转换链路，暂不承诺原版式 |
| 压缩包与未知二进制 | 类型/大小/路径信息与外部打开 | 目录清单后置；禁止把乱码当文本预览 |

P-01：一个统一 Preview 页面承载上述格式。P-02：默认只读。P-03：从消息引用、文件树、Diff、摘要卡均可进入。P-04：独立滚动、查找、复制选区、加载/错误状态。P-05：预览与 diff 是同一文件对象的不同视图，不要求用户重新找路径。

### 3.5 浏览器（B 系列，必做）

- B-01：明确且始终可发现的浏览器入口；“浏览器”和“文件预览”分别命名，避免都叫 Preview。
- B-02：地址栏、导航、前进/后退、刷新/停止、页面标题、加载与错误提示、在系统浏览器打开。
- B-03：多个网址标签/实例，页面可以移到左、右、底，正常导航不被会话切换强制重置。
- B-04：WebView2 缺失、初始化失败、证书/导航失败有可操作反馈。
- B-05：打开 localhost 服务与本地 HTML；本地文件、普通网页和 agent 生成页面标明来源。
- B-06：浏览器不自动获得 Pi 操作权限；页面访问不等于 agent 已能读取/控制页面。

### 3.6 终端（T 系列，必做）

- T-01：真实 Shell，会话标签、新建/关闭、项目 cwd、Shell 选择与进程退出状态。
- T-02：正确文本布局、ANSI 颜色/光标/清屏、换行、滚动历史、选择复制、粘贴、中英文输入和组合字符。
- T-03：窗口缩放传递给 PTY；长行、宽字符、emoji、交互命令、全屏 TUI 纳入验证矩阵。
- T-04：终端与 agent 工具日志分开；不能把一段文本输出当可交互终端。
- T-05：关闭正在运行的终端显示对象与后果；收起/移位不结束进程。
- T-06：优先评估成熟终端渲染引擎，并保留现有 ConPTY 进程层；不继续把自绘“基本能显示”当完整终端。是否使用 WebView2 内嵌成熟渲染器另行评审，不在本轮替换技术栈。

### 3.7 侧栏提问（Q 系列，必做）

- Q-01：独立输入框、流式回答、停止、复制，带清晰的“旁路提问”身份。
- Q-02：可选择当前选中文本、指定消息、当前文件或 diff 作为上下文；发送前可见具体对象。
- Q-03：默认只读解释，不继承主任务的写入权限；若需要工具，先定义独立审批规则。
- Q-04：不往主会话偷偷插入旁路消息；回答可以显式“引用到主会话”，不会自动执行。
- Q-05：建议独立子会话/进程，不共享一个 Pi 进程中的并发 prompt。须核实 RPC、锁、存储及成本契约后再接线。
- Q-06：切换主会话时绑定的上下文如何变化必须明确；草稿保留，已有回答的来源不被改写。

## 4. 中央主对话

### 4.1 会话头（C 系列）

| 编号 | 位置 | 内容 |
|---|---|---|
| C-01 | 左上 | 会话名称、项目、重命名、返回概览；只保留会话级动作 |
| C-02 | 右上 | 查找本会话、轮次目录/刻度开关、摘要卡开关、会话更多菜单 |
| C-03 | 更多菜单 | 分支管理、导出、归档；未来分享/朗读入口按能力接入 |
| C-04 | 详情浮层 | 模型、连接、运行状态、用量、上下文占用和审批策略；错误可见且可追踪 |
| C-05 | 会话内搜索 | 文本查找、匹配数量、上一/下一结果；不能与全局搜索混为一谈 |

### 4.2 消息与内容渲染（M 系列，必做）

- M-01：完整 Markdown 解析与渲染：段落、标题、列表/嵌套列表、引用、表格、链接、图片、分隔线、代码块及转义。优先成熟解析器，不继续扩大手写字符串解析。
- M-02：代码块语言、行号、复制、长内容展开/收起、横向滚动、常见语法高亮；不挤破阅读列。
- M-03：`$$...$$` 块级数学必做；建议同时支持 `$...$` 行内数学与 `\(...\)` / `\[...\]`。公式解析不得进入代码块；货币符号和未闭合流式片段不误判。
- M-04：Mermaid 建议纳入基础内容能力：图形渲染/源码切换、放大、解析失败提示。与网络无关的离线资源优先，图中脚本/链接按策略处理。
- M-05：流式片段暂不完整时稳定降级，结束后重新解析；不能每 token 全量重建导致闪动、失焦和滚动跳动。
- M-06：思考与工具块可折叠；工具状态、审批、失败、耗时与最终结果来自真实事件。
- M-07：历史加载与实时消息使用同一渲染路径，支持选择复制、链接打开、附件进入预览。
- M-08：各消息提供稳定定位点；可引用到侧栏提问，不靠文本复制猜测来源。

### 4.3 消息操作（A 系列）

操作条归属具体消息/轮次，不将整会话操作和消息操作混在一起。可用条件必须根据消息状态、角色和底层契约决定。

| 编号 | 操作 | 基础规划 | 约束 |
|---|---|---|---|
| A-01 | 复制 | 必做：复制完整回答、代码块、用户请求 | 默认 Markdown 原文；可选纯文本 |
| A-02 | 分支 | 必做：从指定历史点创建新会话 | 保留父会话与分支点，不改写原会话 |
| A-03 | 重试 | 必做：失败重试/重新生成有明确区别 | 已执行工具有副作用时不能盲目重放；建议从请求前创建分支 |
| A-04 | 引用/旁路提问 | 必做：选区或整条消息进入侧栏上下文 | 显示来源，不自动发送 |
| A-05 | 评价 | 建议下一阶段：赞/踩、本地反馈备注 | 未有接收端时明确为本地记录，不声称训练或上传 |
| A-06 | 分享 | 建议下一阶段：本地导出优先，公开链接后置 | 预览分享范围并处理凭据/私人路径；没有服务不显示假链接 |
| A-07 | 朗读 | 建议下一阶段：开始/暂停/停止与声音设置 | 系统 TTS 能力核实；代码/公式朗读策略单独定义 |
| A-08 | 用户消息编辑 | 后续：改写后从该点创建分支 | 不修改已有执行历史；不作为基础版前置 |

### 4.4 快速摘要卡与轮次刻度（S 系列）

- S-01：会话右上摘要卡类似用户参考图：会话/任务名、来源、文件变更摘要、进入变更页、更多菜单。
- S-02：摘要折叠后变为顶部小入口；展开参与中央内容布局，不悬浮压在正文或输入框上。
- S-03：文件数、状态及来源来自实际报告；没有变更显示无变更，加载失败显示失败，不填假统计。
- S-04：左缘轮次刻度标记用户请求/任务段；点击定位消息，当前位置高亮，悬停显示摘要。
- S-05：刻度、概览中的当前会话目录、搜索结果共享稳定消息 ID；长会话不因虚拟化丢失定位。

### 4.5 主输入区（I 系列）

- I-01：多行草稿、中英文 IME、发送/停止、排队/插队的真实状态。
- I-02：模型与思考等级、附件/文件/消息引用、斜杠命令；不把独立动作塞进无说明文本。
- I-03：草稿按会话保存，切会话不丢；未发送附件可移除。
- I-04：审批等待、断线、失败、模型不可用与发送禁用有明确原因。
- I-05：队列可见，编辑/取消仅按 Core 实际能力；前端删除后不会被后续事件复活。
- I-06：长输入有高度上限与内部滚动，始终留出阅读区；收起周边面板不改变草稿。

## 5. 设置、扩展与通知

独立设置保留模型/供应商、代理、凭据、审批与工具、界面/布局、快捷键、通知、数据/诊断分类。显示已保存/未保存/需重启的状态；离开未保存页面提供明确处理。

扩展管理可从统一概览和命令面板进入，沿用官方 Pi 扩展能力。通知中心汇总完成、失败、待审批和需要用户动作的信息，并可返回所属会话。系统通知的注册和投递必须单独实测。

全局状态底部显示项目/连接/活动与必要诊断入口。扩展错误、无模型或页面不可用不靠用户查看终端才能发现。

## 6. 当前实现对照（源码核查，不是实机验收）

| 模块 | 现状 | 需要补齐 |
|---|---|---|
| 布局 | 固定左/右/底；尺寸持久化 | 通用宿主、迁移、排序、页面实例与布局存储 |
| 概览 | 会话列表、重复导航、命令面板 | 合并入口、消息目录与一致的可用状态 |
| 浏览器 | WebView2 宿主、地址栏、右区 Preview | 命名与入口收口、与文件预览区分、多实例、实机验证 |
| 终端 | ConPTY + 自写缓冲/字符格渲染 | 修渲染、选择/粘贴/IME、成熟引擎评估及真实交互验收 |
| 文件 | 简单浏览、HTML/图片/文本预览 | 文件树、格式矩阵、Markdown/PDF、统一文件上下文 |
| Diff | Core 有逐行查询；UI 主要是文件状态 | 逐行渲染、预览切换和真实统计 |
| 旁路提问 | 未发现 | 独立上下文、会话与权限契约及页面 |
| 主消息 | 轻量 Markdown、代码复制、思考/工具块 | 完整 Markdown、数学、Mermaid、消息操作条 |
| 分支 | Core 有 ForkAsync | 历史点 UI、分支导航、父会话归属 |
| 顶部与刻度 | 详情浮层、工作区开关、滚动到底 | 摘要卡、搜索、轮次刻度 |

## 7. 实施路线与依赖

串行推进，每个增量先明确可观察行为，再实现、验证、提交。确需独立研究时临时委派，不重新建立常驻多轨道。

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| 0：产品定案 | 本文 + HTML 示意，确认页面、默认布局、消息动作和格式范围 | 用户明确基础版范围；示意不直接当已实现产品 |
| 1：开发循环 | 固定开发版入口；修改后构建/重启；数据隔离可选；日志可定位 | 能打开最新构建并确认版本，不依赖安装器 |
| 2：宿主与导航 | 三通用停靠区、移动/排序/关闭/保存；统一概览 | 所有现有页迁入宿主；不同尺寸不重叠；重启恢复 |
| 3：内容阅读 | Markdown、数学、Mermaid、完整复制、消息定位和轮次刻度 | 流式/历史/长内容/解析失败矩阵通过 |
| 4：检视页面 | 文件树、统一预览、Diff 接线、独立浏览器入口 | 每类文件有支持或明确降级，入口与状态一致 |
| 5：交互辅助 | 终端质量收口、侧栏提问、分支、重试与摘要卡 | 真实 Shell 与真实 Pi 工作流验证，副作用与审批边界清楚 |
| 6：体验收口 | 视觉走查、错误恢复、快捷键、长会话性能 | AI 先解决明显错误，用户集中体验并定视觉取舍 |
| 后续 | 评价、导出/分享、朗读、Office/压缩包深度预览 | 不阻塞前述基础任务；用户可调整优先级 |

终端和侧栏提问虽然安排在阶段 5，仍属于基础版必做；安排体现契约和宿主依赖，不代表取消。Mermaid 建议基础版加入，但其“如果可以”的用户措辞保留为可协商项。

## 8. 验证与交付规则

- 无头测试用于状态、布局尺寸、动作可用性、数据来源和渲染样例；截图检查内容可见、文字不溢出、无重叠。
- 实机测试用于 Windows DPI、IME、焦点、WebView2、ConPTY、窗口移动及真实 Pi 会话。无头通过不替代实机。
- 每修复一个实际问题沉淀一个最小复现场景或断言，不靠放宽断言通过。
- 每个功能至少覆盖正常、空、加载、失败、不可用、长内容/窄窗口状态。
- 终端验收覆盖中文、emoji、组合字符、颜色、清屏、滚动、resize、粘贴和至少一个 TUI；不把纯文本 echo 当完整验收。
- 对布局检查左/右/底每个页面都能放置，移位不丢状态；正常桌面、1024 宽和高 DPI 必须有证据。
- 不运行无关全仓回归；涉及共享宿主和 Core 契约时执行相关组，集成交付按实际风险跑完整套件。
- registry 记录实际数字、退出码和未验证项；源码存在、mock 示例和静态 HTML 分别标注证据级别。

## 9. HTML 示意覆盖与限制

可操作：三个区域的页面切换/添加/关闭/收起、菜单移位和跨区拖动、鼠标调整尺寸、布局本地保存/恢复、会话切换、消息刻度定位、摘要折叠、预览类型切换、浏览器示例地址、假终端输出、旁路提问示例、消息操作反馈、命令目录与独立设置往返、明暗主题。

不提供：真正文件读取/写入、真实 diff、真正浏览器/联网、Shell、Pi 调用、模型输出、公式/Mermaid 解析、系统 TTS、分享服务、桌面 DPI/IME 验收。数学和图示是固定样例，Office 是降级示例。所有点击结果只修改示意页面的本地状态。

HTML 是结构与交互讨论稿；不会替代 Avalonia，也不建议把 HTML 原封不动嵌进产品主会话来规避架构问题。

## 10. 建议本轮确认的四个决定

1. 同意“中央主对话 + 三个通用停靠区”，默认左概览/文件、右检视/提问、底终端；布局可自由修改。
2. 基础版必须交付概览、文件、Diff、预览、浏览器、终端、侧栏提问，以及 Markdown/数学、复制/分支/重试、摘要卡和刻度。
3. Mermaid 建议一起交付；评价、分享、朗读和高级 Office 预览可后置，避免把基础版扩大为无限清单。
4. 先把开发版启动和通用宿主做稳，再按依赖串行收口内容与功能；AI 主动走查，用户集中验收。
