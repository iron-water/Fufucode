# 页面设计原则

日期：2026-10-21。本文从设置页的实践抽象而来，适用于设置、工作台、插件页、对话页、弹窗和浮层。设置页是参考实现，不是要复制的模板。

## 一、先定页面契约

每个页面在画控件之前必须能回答：

| 项 | 要求 |
|---|---|
| 页面 ID | 稳定、唯一，可被导航、快捷键、深链和测试引用 |
| 页面目的 | 一句话说明用户来这里完成什么；一个页面只做一类事 |
| 承载形态 | 全屏页、侧边栏、独立 UI、胶囊按钮或藏点；按能力分级选择 |
| 入口 | 导航、动作、命令面板或上下文入口；入口必须真实可达 |
| 出口 | 返回哪里、恢复什么状态、未保存内容怎么处理 |
| 能力 | 依赖的插件/服务是否可用；不可用时显示真实原因 |
| 持久化 | 哪些状态保存、保存在哪个唯一真源、何时生效 |
| 所有者 | 哪个模块负责页面生命周期与释放 |

页面契约不清，后面的布局和样式都会变成猜测。

## 二、承载形态先于页面内容

- 重任务、长期停留、需要视口 → 全屏页或侧边栏。
- 单次决策、轻量确认 → 弹窗、抽屉、浮层。
- 高频单步 → 顶栏胶囊按钮。
- 低频小动作 → 左右辅助栏、动态岛、状态栏等藏点。
- 不要把完整页面塞进弹窗，也不要把一次性确认做成独立页面。
- 同一功能只选一个主承载形态；需要双形态时明确主形态与降级形态。

## 三、结构最多三层

```text
页面 Shell
├─ 页头 / 导航（标题、面包屑、返回、页面级动作）
├─ 分区 Section（组标题 + 内容）
│  ├─ 行 Row（一个设置/一个对象/一个动作）
│  └─ 非行式块 Panel（说明、列表、预览、编辑器）
└─ 页面级状态（加载、空、错误、不可用）
```

规则：

1. 一个页面只有一个滚动所有者；内部列表需要滚动时给明确高度上限。
2. 分区不包“大卡片套小卡片”；行是独立表面，组只负责间距。
3. 一行只承载一个决策或一个对象；不要把多个开关塞进一行。
4. 行结构固定：图标（可选）+ 标题 + 说明（可选）+ 右侧控件/箭头。
5. 可点击整行时，行内按钮/开关不得重复触发行点击。
6. 破坏性动作与普通动作分开；危险动作需要对象与后果说明。

## 四、构件与样式只有一个来源

- 页面 Shell、Section、Row、Panel、Badge、Toolbar 必须有共享构件；不要在页面里手写平行卡片。
- 样式集中在共享样式表；页面只加语义类，不写局部 `Style`。
- 设置页的 `settings*` 类只服务设置页，不要复制到其他页面；其他页面应使用自己的语义构件，或把通用部分提取成共享构件。
- 颜色、圆角、字号、间距只用语义 token；禁止裸 hex、内联圆角和临时字号。
- 新增语义类必须同时有：定义、使用点、文档说明、测试守卫。

## 五、视觉节奏固定

- 间距用 4 的倍数：4/8/12/16/20/24/32；组内 8，组间 24/32，页边 20/24。
- 字号分层：页面标题 22–28，分区标题 14，正文 14，说明/meta 12；不出现 13/15/18 等中间值。
- 圆角分层：控件 4，卡片 6，浮层 8，胶囊 16；同一层不混用。
- 页面内容有最大阅读宽度；宽屏不把正文拉成超长行。
- 首个分区不加上间距；后续分区使用统一切口，不靠页面手调。

## 六、颜色服从语义

- Fluent 暗色：三档底色（窗口/一般栏/高亮）+ 一种主题色 + 一种模型输出强调色。
- 主题色服务 UI；强调色只服务模型输出标记；两者不混用。
- 状态色只表达成功/警告/错误/信息；diff 红绿、代码高亮、终端、图标是明确例外。
- 不靠颜色单独传达状态；状态同时有文字或图标。

## 七、状态必须完整且诚实

每个页面至少设计这些状态：

| 状态 | 要求 |
|---|---|
| 加载 | 明确的加载反馈，不用空态冒充 |
| 空 | 说明为什么空、下一步做什么 |
| 错误 | 原因、影响、重试/恢复入口 |
| 不可用 | 缺哪个插件/服务/权限，如何安装或启用 |
| 禁用 | 为什么禁用；不能用禁用按钮掩盖缺失功能 |
| 未保存 | 草稿状态、保存、丢弃、离页处理 |
| 已保存/已应用 | 区分“已保存”和“当前已生效” |
| 待重启 | 说明重启后生效的范围 |
| 部分成功 | 如实列出成功/失败项，不合并成成功 |

禁止：假开关、假成功、假空态、假统计、未接线按钮、占位页。

## 八、响应式是重排，不是隐藏

- 窄窗：右侧控件移到说明下方或下一行；不横向溢出。
- 不因窄窗隐藏功能；必要时折叠为菜单或下钻页。
- 断点由内容决定，不由设备名决定；至少验证窄、常规、宽三档。
- 切页/重排后保留滚动位置、焦点、选中项和草稿。
- 抽屉/浮层关闭后焦点回到触发点。

## 九、交互与可访问性

- 所有可点击控件有可读名称、键盘可达、焦点可见。
- Escape 先关闭最内层浮层，再处理页面返回。
- 中文 IME 组合期间 Enter 不触发提交。
- 行级点击与内部控件点击边界明确；不出现“点哪里都能触发”的意外。
- 破坏性动作明确对象、范围与后果；不提供未实现的“永久允许”。
- 搜索必须能命中页面内条目，并说明结果范围；无结果不残留空组头。

## 十、性能是页面结构的一部分

- 页面按需创建；不可见的重页面不提前构建。
- 长列表虚拟化；长文本分段/截断；大量图片延迟加载。
- 流式更新只更新变化块，不每 token 重建整页。
- 视觉树稳定：切换页面保留实例，避免重复订阅和焦点丢失。
- 页面销毁时释放事件、定时器、子进程和插件贡献。

## 十一、验证是设计的一部分

- 行为测试：入口可达、关键控件可交互、状态变化真实。
- 源码守卫：无局部样式、无裸 hex、无未知资源键、无平行卡片类。
- 截图矩阵：宽/窄、亮/暗、空/错误/加载、长内容。
- 每个新页面至少覆盖：正常、空、加载、错误、不可用、窄窗。
- 未运行项写“未验证”，不靠放宽断言通过。

## 十二、设计审查十问

1. 这个页面只做一件事吗？
2. 入口和出口都真实可达吗？
3. 承载形态选对了吗？
4. 结构是否超过三层、是否出现卡片套卡片？
5. 每行是否只有一个决策？
6. 是否复用了共享构件和语义 token？
7. 九种状态是否都有真实呈现？
8. 窄窗是否只重排、不隐藏功能？
9. 键盘、焦点、IME、焦点返回是否成立？
10. 有没有测试能证明这些，而不是只靠肉眼？
