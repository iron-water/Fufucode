# Fufucode 项目总原则

日期：2026-10-21。本文是跨模块架构总纲；具体产品决定以 [decisions.md](../decisions.md) 和用户最新决定为准，设置页细则见 [settings-design-spec.md](../settings-design-spec.md)。

## 1. 单一事实源

- 设置分类只认 `SettingsNavCatalog`。
- 动作只认 `AppActionRegistry` 与 `WorkbenchActionDefaults`。
- 工作台页面只认 `WorkbenchPageRegistry`。
- 插件安装/启用状态只认 `plugins.json` 与 `PluginStateNotifier`。
- 禁止在 VM、XAML、硬编码数组里维护第二份页面、动作或状态清单。

## 2. 分层边界

- `Core` 不引用具体后端；`App` 不静态依赖可选插件。
- 插件未安装、未启用、加载失败时如实报告不可用，不回退到其它引擎。
- 跨后端能力走 `ISessionCoordinator`、`IRpcClientFactory`、`IBackendSessionFactory`、`BackendId` 等公共接口。
- 页面壳与插件内容分离：内建页可以保留，插件只提供内容与生命周期。

## 3. 显示分级是契约

- 物理承载、`UiActionPosition`、动作默认位置、会话岛磁贴、状态栏必须读同一份配置。
- 用户改了位置、顺序或隐藏状态，渲染器必须跟随。
- 设置里的入口必须能到达真实执行点；没有实现的页面不得以占位页存在。

## 4. 能力诚实

- 未安装、未启用、运行时不支持、加载失败都要显示真实原因。
- 禁止假开关、假成功、空实现按钮、“尚未接线”占位页。
- 设置项只做三件事：改配置、显示真实状态、把用户送到真实执行点。

## 5. 生命周期与所有权

- 同一会话、同一工作树、同一插件页面只能有一个写入者。
- 插件页注册与内建页壳分离；插件失败不得删除 core/optional 注册。
- 动态动作、事件订阅、管理器在卸载时必须撤销。
- 跨实例状态通过通知收敛，不依赖各自内存快照。

## 6. 插件优先、小核心

- 新增功能先判断能否独立安装、更新、禁用、卸载。
- 可选实现及专属依赖不得随默认包发布。
- 默认安装策略与架构拆包分开；未安装必须报告不可用。

## 7. 构件与样式单一来源

- Fluent 暗色只用三档底色、一种主题色、一种模型输出强调色；细则见 [color-principles.md](color-principles.md)。
- 设置页所有行经 `SettingsLayout`；样式集中在 `WorkbenchStyles.axaml`。
- 颜色、圆角、字号、间距只用语义 token；禁止内联修补、裸 hex、平行卡片类。
- 设计纪律必须能由源码测试机械检查。

## 8. 可验证性

- 测试必须证明“设置操作 → 显示分级 → 页面/工具/服务真实变化”。
- 失败先区分主链路缺陷、并行重构阻塞、既有环境基线。
- 不得靠放宽断言制造通过；未运行项写“未验证”。

## 9. 简洁与去重

- 删除没有生产调用的辅助实现、重复动作、重复页面清单、重复更新链路。
- 不为“以后可能用”保留空抽象。
- 工程验收包含 0 错误、0 警告，而不是只看功能能跑。

## 10. 对用户需求忠实

- 用户看到“终端设置”，必须能到达终端或真实配置。
- 用户看到“安装插件”，必须真的安装或给出失败原因。
- 用户看到“检查更新”，只能有一条更新行为。
- 文档、测试、代码必须说同一件事。

## 审查清单

- [ ] 这个入口有唯一目录和唯一状态源吗？
- [ ] 它最终到达真实动作/页面/工具吗？
- [ ] 不可用时显示了真实原因吗？
- [ ] 生命周期结束时撤销了订阅、页面和动态动作吗？
- [ ] 是否有测试证明三层链路，而不是只测两个布尔值？
- [ ] 是否删除了旧路径、重复清单和死代码？
- [ ] 构建是否 0 错误、0 警告？
