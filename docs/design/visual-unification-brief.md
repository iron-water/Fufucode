# Fufucode 视觉与交互统一：设计交接任务书

日期：2026-10-07。来源：用户设计理念陈述（产品所有者原话整理）。本文是设计理念与重构边界，**不代表下列候选功能均已实现**；功能现状以源码与 `docs/records/` 实测记录为准。

## 0. 口径与优先级

- 本文优先于 `docs/design/frontend-design-guideline.md` 中的"固定五区骨架"表述；该文件的 UniGetUI 令牌锚点（§6.2、§7.1）继续有效。
- 功能页面清单沿用 `docs/design/frontend-functional-plan.md`（L/N/F/D/P/B/T/Q/C/M/A/S/I 编号），重构不得删减其已实现项。
- 设计依据：`docs/research-results/R05/customization-demo.html`。功能基线：当前 `main`（`f733a12` 起）的实际应用。
- 视觉参考：只读克隆 `reference/UniGetUI`。最新 UniGetUI 色调要求优先于早期 Demo 的绿色默认值（见 `docs/decisions.md` 2026-10-07）。
- 一句话目标：让 Fufucode 成为视觉统一、阅读舒适、交互完整、可深度定制的原生 AI 开发工作台，同时保留 R05 已确定的结构与能力。

## 1. 产品定位

Windows 原生、以 AI 编程会话为核心的开发工作台。

- 中央会话承载主要工作：提出任务、阅读过程、处理权限、检查结果、继续迭代。
- 文件、变更、预览、浏览器、终端等页面围绕会话提供上下文。
- 体验安静、清晰、精致，适合长时间工作。重点是工作流完整、信息组织合理、操作顺手；视觉服务于这些目标。

## 2. 整体架构

保留 R05 Demo 和现有功能框架，在其上统一视觉与交互。

- 结构：顶部全局栏、中央会话、左／右／底部停靠区域、底部状态栏。
- 左、右、底是三个**通用容器**。页面可移动；不得重新做成用途固定的独立侧栏。
- 默认：左＝概览、文件；右＝变更、文件预览、浏览器；底＝终端。
- 引用草稿、会话目录、侧边聊天等页面遵循同一套停靠规则。
- 设置是独立页面，不得退回临时抽屉。
- 支持受控的移动、排序、固定、关闭、重新打开、调整尺寸、恢复布局。不引入无限嵌套的自由停靠系统。

## 3. 信息与操作层级

用户始终知道：自己在哪里、当前操作影响什么、接下来能做什么。

- 全局操作、会话操作、单条消息操作分层放置，不混成一排。
- 同一功能的多个入口（菜单、快捷键等）共享行为、状态和命名。
- 高频操作直接可见；低频进入菜单；高级配置进入设置。
- 页面切换保留上下文。文件树、变更列表、预览之间连续衔接。
- 侧边聊天是独立会话；向主会话传递内容必须是显式操作。
- 所有侧边栏 Tab 形成完整工作流，不能只有外观和可点击按钮。

## 4. 视觉语言

以 UniGetUI 的 Windows 原生质感为主要参考，统一整个应用，不只是改背景色。

- 默认跟随系统明暗主题和强调色；保留用户自定义任意颜色。
- 统一背景层级、控件表面、分隔线、文字颜色，以及悬停、按下、选中、焦点状态。
- 标题栏、菜单、弹窗、设置页、工作区属于同一套视觉系统。
- Fluent、玻璃、平面、拟物可作为风格预设，但不得改变功能结构。
- 玻璃效果克制，保证文字对比度，提供可靠的实色回退。
- 避免大标题、装饰性渐变、过多胶囊标签、层层卡片、重复边框。用留白与层级组织信息。

## 5. 中央会话

中央区域首先是高质量的阅读与输入空间。

- 用户消息、助手消息、工具过程、权限请求、结果摘要容易区分。
- 正文突出；时间、模型等元信息退居次要层级。
- 普通文本有舒适阅读宽度；代码、公式、表格按自身结构布局，不被强行压窄。
- Markdown 与富内容在流式输出、历史记录、加载失败时保持稳定。
- 消息操作对应具体消息或轮次；头像、正文、操作栏分别可识别、可配置。
- 摘要折叠后成为简洁入口并参与正常布局，不悬浮遮挡正文或输入框。
- 输入区保留：多行输入、中文输入法、附件、模型与思考强度、权限、发送／停止状态。
- 附件和引用标明来源，可检查、可移除。窄空间下控件换行，不消失、不互相覆盖。

## 6. 微观交互

交互完整性与视觉精致度同等重要。

- 每个二级页面和弹窗都有明确退出路径：返回、取消、关闭或 Esc。
- 弹窗右上角关闭等同取消，不触发默认确认。
- 菜单关闭、页面返回后，焦点回到合理位置；未保存和运行中的状态需明确处理。
- 隐藏区域、关闭页面、终止进程是三种不同操作。移动终端不重启进程；切换页面不丢失会话。
- 图标准确表达功能，统一风格、尺寸、线条、对齐。不用一个通用图标代替多个不同动作。
- 不熟悉的图标提供提示；选中、禁用、加载、错误状态清楚可辨。
- 空白、无结果、失败、离线、等待批准、完成、能力不支持分别表达；不用假数据制造完整感。

## 7. 定制与反馈

普通用户开箱即用，专家用户可深入调整。

- 设置保持四类：外观、布局与停靠、细节与功能、配置文件。
- 可调：主题、颜色、字体、密度、圆角、阅读宽度、区域尺寸、操作入口的显示与位置。
- GUI 与 JSON 表达同一套配置；支持全局默认、项目覆盖、导入导出、撤销恢复。
- "恢复布局"与"恢复全部默认设置"必须区分。
- 保留全组件意见反馈：能准确指向头像、正文、按钮等具体对象。
- 意见模式下左键收集意见、不执行原操作；右键追加意见时保留原有菜单。重构后既有意见仍可追溯（目标标识不得因重构失效）。

## 8. 重构边界（硬约束）

可以重组：视觉组件、样式资源、交互表达。必须保护：

- Avalonia 原生架构；官方 Pi RPC（不虚构命令，以 `docs/runtime-baseline.md` 为准）。
- 会话与进程归属（SessionLease 等）；配置兼容性（全局 JSON + 项目稀疏覆盖、未知键保留）。
- 稳定的页面标识与消息标识（意见反馈与布局 JSON 依赖它们）。
- 做法：优先建立共享设计变量（令牌）与共享组件，让各页面自然一致；避免逐页堆叠特殊样式。

## 9. 验收门

实施前按本节确定每个增量的验收条件；未实际运行的项标为"未验证"。

| 维度 | 必查内容 |
|---|---|
| 主题 | 明、暗、跟随系统；自定义强调色；玻璃预设的实色回退与正文对比度 |
| 窗口 | 宽窗、窄窗（溢出菜单、换行、无遮挡/裁切） |
| 页面 | 九个停靠页 + 设置四类，逐页完整工作流 |
| 退出路径 | 每个二级页/弹窗：返回、取消、关闭、Esc；关闭＝取消 |
| 状态保留 | 移动/隐藏/关闭页面不丢会话、不重启终端；焦点回归 |
| 图标 | 语义准确、风格统一、有提示 |
| 遮挡 | 摘要折叠、输入区、浮层不覆盖正文 |
| 兼容 | 旧配置 JSON 可读；既有意见目标可追溯 |

- 构建与测试通过只说明技术检查通过。
- **最终视觉验收**＝与 UniGetUI 对照截图 + 产品所有者确认。agent 不得自行宣称视觉验收通过。
