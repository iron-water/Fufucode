# 浮窗（2026-10-08）

新窗口「浮窗」：承载四类会话事件提醒，并提供辅助对话入口。按用户答复实现，四个待定项的选择记录在本文末尾。

## 形态与 pin

| 状态 | 形态 |
|---|---|
| pin（默认） | 主窗口内悬浮面板，不占停靠位，可拖动，右上角图钉切换 |
| 取消 pin | 脱离成独立窗口，位置与尺寸写回偏好文件 |

两者共用同一个控件实例，切换时先解挂再挂载（控件只能有一个父级）。实测切到独立窗口后内容完整、无重复实例。

## 四类会话事件

浮窗"提醒"分区直接绑定通知中心，因此四类事件与现有语义完全一致：

- 任务已完成（`TurnSettled` + `Completed`）
- 任务失败（`TurnSettled` + `Failed`）
- 会话连接中断（连接故障 / 进程退出 / 协议错误）
- 有一项权限或问题待处理（扩展 UI 请求）

每条带类型符号、标题、说明、时间与"返回会话"跳转。未读与待处理状态沿用通知中心已有的标记，不另建一套。

## 投递渠道

三路可独立开关，默认**浮层 + 浮窗都开**，Windows 预留：

- **浮层**：现有应用内底部浮层，由通知中心的失焦策略决定何时弹。
- **浮窗**：事件写入浮窗列表。
- **Windows**：设置项可开可存，但**本轮不投递真实系统通知**。未打包 Win32 应用要真正弹系统通知，需要注册 AppUserModelID 并引入通知依赖，属于安装器/打包范畴，按用户答复本轮不做，界面已说明"尚未接入"。

关掉浮层渠道后浮层立即消失，浮窗渠道不受影响。

## 出现时机

沿用现有失焦策略（审批按"通知审批"开关、完成/失败按"仅失焦"），未新增打扰规则。

浮窗本身**不常驻**：列表为空且用户未手动唤出时不可见，避免空面板长期压住工作区。有提醒或用「显示/隐藏浮窗」动作唤出时才出现。关闭浮窗后新事件不会把它弹回来（等同放弃该渠道），提醒回落浮层。

## 辅助对话

浮窗"辅助对话"分区复用**同一个侧边聊天控件**，在浮窗与停靠页之间迁移，而不是新建会话。因此不存在两份聊天、也不会多起一个 Pi 会话。取消 pin 或切回提醒分区时，辅助对话自动送回停靠页。

至此"侧边聊天"这个页面不再是我上一轮说的重复入口——它是同一个控件的一个宿主位。

## 设置

「功能」页右栏新增「浮窗」一组：显示浮窗、固定到应用内、在浮层提醒、在浮窗提醒、Windows 系统通知，以及当前渠道摘要。偏好存 `floating-window.json`（应用数据目录），与 `ui.json` 分离，互不覆盖。

## 开发中修掉的两个真实缺陷

1. **控件重复挂载**：首次切到独立窗口时抛 `already has a visual parent`。原因是内嵌宿主未先解挂。现在两个方向切换都先清空旧父级。
2. **偏好无法保存**：浮窗底部一度显示 JSON 序列化失败。原因是未定位时位置用 `double.NaN` 作默认值，而 `System.Text.Json` 默认拒绝 NaN。已改为写入 null、读取回落 NaN。

第二条只靠自测不会暴露（用例不读底部文字），是看截图发现的。
