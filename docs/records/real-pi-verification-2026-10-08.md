# 真实 Pi 后端端到端核验（2026-10-08）

用电脑操作功能，在真实 Pi 后端（非 mock）下核验前端可用性。**只核验前端**：功能实现由 Core/Pi 负责，不在本文范围。

## 环境

| 项 | 实际值 |
|---|---|
| 应用 | `tmp/vu9-build/Fufucode.App.exe --project <临时项目>` |
| 项目 | `tmp/realcheck/project`，临时 git 仓库（README.md、calc.py） |

## 核验过程与结果

### 1. 启动与初始化
应用以真实模式启动，标题为「真实 Pi 会话」，非 mock 演示。输入区、模型选择、思考等级、权限模式四个控件都解析到真实值。

### 2. 首次任务（人工确认模式）
输入"请读取项目里的 calc.py，然后新建一个文件 result.txt，内容写 add(2,3) 的计算结果"并发送。

观察到的前端行为：

- 用户消息正确进入时间线，时间戳显示 `01:50`（不再出现 `00:00:00` 占位）。
- 发送后控件切换为「排队 / 插入 / 停止」，符合运行中语义。
- Pi 请求 `write` 工具授权时，审批以**独立原生窗口**「Fufucode 审批」出现，含允许/拒绝按钮；批准后会话继续。
- 时间线按序渲染：思考过程（可折叠）→ `read` 工具卡（显示 `{"path":"calc.py"}`）→ 思考过程 → `write` 工具卡（显示 `{"content":"5\n","path":"result.txt"}`）→ 助手正文。
- 「本轮变更」显示「写入 · result.txt」，「生成产物」列出 `result.txt` 且为可点按钮。
- 消息操作按钮（复制/引用/编辑/侧边提问/更多）齐全。

磁盘核对：`result.txt` 内容为 `5`。前端展示与磁盘一致。

### 3. 权限模式切换到完全访问
在下拉中选择「完全访问」，弹出确认框「完全访问：工具无需人工确认」，含「允许本会话所有工具」「取消」与说明文字。批准后模式生效。

### 4. 第二次任务（完全访问模式）
输入"请运行 python calc.py 同级目录下的计算，把 add(5,7) 的结果写入 sum.txt"并发送。

**关键证据**：`bash` 工具两次调用（`python calc.py`、`python -c "import calc; print(calc.add(5,7))"`）**均未弹出任何审批窗口**，直接执行。全过程中系统里只有「Fufucode」一个窗口。

磁盘核对：`sum.txt` 内容为 `12`，且项目下出现 `__pycache__`（Python 实际执行痕迹）。完全访问确实跳过了审批。

## 发现的前端问题

### 模型连接中断时的错误展示（已如实呈现，无需改动）
第二次任务期间出现「模型失败 Connection error」与「未知错误 Connection error」两条错误条目，同时任务实际已完成。核对后确认：这是模型侧连接中断的真实反映，错误条目与工具成功记录并存，没有掩盖真实状态，也不属于前端缺陷。右上角通知文案「本轮未成功，请返回会话查看错误」准确。

### 浮层通知会覆盖会话正文（未修复，记为待办）
`NotificationPrompt` 固定在窗口右上角、悬浮于时间线之上。当通知出现且时间线内容顶到该位置时，正文会被浮层压住。交接说明要求"摘要折叠后……不能悬浮遮挡正文或输入框"，同一条原则应适用于通知浮层。

尝试改为贴在窗口底部操作带上方，但底部区域是行高为 0 的状态栏行（状态栏默认关闭），贴着它会变成不可见，因此回退未改。需要与用户确认通知浮层的期望位置后再动。
