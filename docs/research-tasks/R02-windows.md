# R02 Windows 多窗口与多进程

遵守 [共同协议](README.md)。允许写入：仅 `docs/research-results/R02/`。

## 需求与问题

用户希望像浏览器一样打开独立窗口，Alt+Tab 快速切换并同时观察多个 agent。不要将多窗口等同于多进程，也不要预设 Windows harness 无此能力。

1. 确认本仓 Avalonia 版本、应用生命周期和 Pi 会话协调器边界；研究同进程多个顶级 Window、每窗口独立进程、共享后台协调器三种方案。
2. Windows Alt+Tab、任务栏分组、窗口标题、焦点、关闭单窗/全应用、跨显示器、最小化和恢复的行为是什么？用官方文档或版本源码支撑。
3. 一个窗口一个会话与一个会话多视图如何区分？同一 Pi 会话只能由谁写入？草稿、排队、授权弹窗、停止命令路由如何防止冲突？
4. 比较 Pi 每会话子进程和共享代理的资源、崩溃、孤儿进程、持久化锁和重启恢复；多进程 IPC 身份与访问控制。
5. 给出“新窗口”“移到新窗口”“复制只读视图”“fork 到新窗口”的语义。支持最大化、最小化、Alt+Tab，不应只是 dock 弹层。
6. 小样本核实 Windows harness 现状，注明版本和能力。给出浏览器相似体验不要求浏览器相同进程架构的解释。

验收：方案对比、窗口/会话/Pi 所有权图、最小双窗 PoC 方案及关闭/恢复验收。建议按成本优先交付真实多窗口，再决定是否要独立进程。系统级小栏暂低优先，不纳入必做。
