# PI-Desktop 功能接入评估：宏观与微观

日期：2026-10-17
输入：`pi-desktop-product-features-2026-10-17.md` 与 `pi-desktop-plugin-integration-2026-10-17.md` 的功能清单
本机基线：`C:\Projects\Fucode\Fufucode` 当前 main
性质：评估报告，不修改生产行为，不构成实施授权

## 方法与结论

宏观维度看四件事：用户价值、战略契合、复用杠杆、成本与风险。
微观维度看四件事：现有接线点是否清晰、数据模型影响、跨后端兼容、可验证性。

结论（2026-10-18 复审后）：

- **现在就该接的 6 项**：权限审批卡升级、AskTool 问题卡、原生失败重试、队列项操作、统一全局搜索、通知收件箱对齐。它们要么是安全地基，要么是低成本高回报。
- **近期接的 7 项**：Plan 契约模式、会话级面板隔离、原生上下文压缩、工作树会话生命周期、会话导入、粘贴转文件、会话状态机。
- **子代理改为“近期打磨”，不再是“后置或从零做”**：2026-10-18 更新已落地第一版进程内子代理；剩余工作是后台化、委派页签、任务控制与隔离工作树。
- **后置或只做插件**：Goal 模式、会话小地图、托盘、设置信息架构、会话悬停卡、远程 SSH、MCP/Skills 管理页。
- **不接**：S3 配置同步、Live Voice、PI 插件运行时兼容层、English-first i18n。
- **最重要的一条宏观判断不变**：不要为子代理再造第二套编排系统。第一版已经复用 `NativeAgentLoop`、工具白名单与审批门；后续增强也必须复用自动开发的任务模型与工作树生命周期，而不是另起一套。

### 仍未变化的能力缺口

以下经源码复核仍然不存在或未升级：

- 无 `ask_user` 工具。
- 无 Plan/Goal 不可变产物与独立审批。
- 审批仍是 60 秒超时、无订阅者自动放行、无风险等级、无 allow-session、无并行审批队列。
- 队列仍无按索引删除/立即发送。
- 原生内核仍无上下文压缩与失败重试预算。
- 停靠布局仍按项目保存，不按会话保存。
- 命令面板仍只搜全局动作。
- 无会话导入、托盘、小地图、会话级悬停卡。

### 修订后的子代理判断

第一版能力：

- 进程内运行，独立上下文、工具白名单、系统提示与最大轮次。
- 继承父会话审批门，变更类工具仍要用户确认。
- 只把最终文本回传父会话，探索过程不污染父上下文。
- 禁止递归子代理；5 分钟硬超时；无并行、无后台任务控制、无 worktree 隔离、无委派页签。

因此：

- **不再建议从零实现**；建议在原实现上补四项：后台执行、`task_wait`/`task_list`/`task_stop`、委派页签、写操作子代理的隔离工作树。
- 宏观判断不变：这些增强必须与自动开发共用任务模型与审批队列。
- 原“子代理后置/插件”结论作废，改为“近期打磨，视需求决定是否继续投入”。

### 修订后的优先级

**第 1 批（安全与日用小闭环，不变）**

**第 2 批（工作区一致性）**

Plan 契约模式 → 原生上下文压缩 → 子代理打磨（后台化、任务控制、委派页签）→ 会话导入

**第 4 批（可选）**
Goal → 小地图、托盘、设置 IA、悬停卡

### 对插件市场报告的影响

`pi-desktop-plugin-integration-2026-10-17.md` 中“`CreatePageContribution` 未被宿主接线”的判断已经过时。当前插件页面可以作为真实工作台页面安装、启用、停用与卸载。原生复刻 PI 插件的路径已经从“需要先补宿主”变为“可以直接做插件包”。其余结论不变：`.piplug` 仍不能直接安装。

## 宏观判断

### 产品定位差异

| 维度 | PI-Desktop | Fufucode |
|---|---|---|
| 技术路线 | Electron + Rust host + Node sidecar | 纯 C# 原生内核 + 可选后端 |
| 扩展方式 | `.piplug` 插件生态，Node API | 原生 C# 插件包，页面/工具/皮肤贡献 |
| 核心卖点 | 插件化工作区与生态 | 零外部依赖、多后端、自动开发闭环 |
| 用户迁移成本 | 高（Node/Electron 依赖） | 低（单包可运行） |
| 风险面 | 插件不可信、权限沙箱不足 | 原生工具审批与内核边界 |

因此，**凡是强化“原生、可信、多会话工作区”的功能优先接；凡是强化“PI 插件生态”的功能不接。**

### 四个宏观过滤器

1. **是否降低核心风险**：工具误写、误删、误执行；长会话上下文溢出；多会话串台。满足者优先。
2. **是否复用现有地基**：审批通道、执行模式、队列、停靠、自动化、Git 工作树。满足者优先。
3. **是否引入新运行时或第二套编排**：引入 Node/Electron、第二套 Agent 调度、第二套通知系统者降级。
4. **是否可独立验收**：能用自测或真实操作证明“拒绝后不执行”“切换会话不串状态”“压缩后可继续”。满足者优先。

## 逐项微观说明

### 1. 权限审批卡升级（现在）

现有链路比上一份报告估计的更完整：

- `NativeCSharpChatSession.RequestApprovalAsync` 在 `manual` 模式询问全部变更工具，`auto` 只询问 `run_command`，`full` 放行。
- 请求经 `ExtensionUiRequest` 发出，`ExtensionUiDialogHost` 弹非模态窗口，用户在 `ExtensionUiDialogWindow` 应答。
- 现状缺口：60 秒超时；无订阅者时自动放行；无风险等级、参数预览、allow-session；并行工具只弹多个窗口，没有队列。

改动建议：

- 扩展 `ExtensionUiRequest` 载荷：`risk`、`argumentsPreview`、`targetPaths`、`allowSessionKey`。
- 在 `NativeCSharpChatSession` 增加会话级已授权工具集合；`allow-session` 只对该工具生效。
- 桌面端无订阅者时返回拒绝而不是放行；CLI 通过 `AutoResponder` 显式放行，保持可用。
- 把超时改为可配置，默认不自动过期；回合取消或窗口关闭才算拒绝。
- 后续子代理审批复用同一队列，不另建通道。

验收：拒绝后工具不执行且模型收到明确拒绝；allow-session 只影响同一工具；重启后不重放。

### 2. AskTool 问题卡（现在）

本机没有 `ask_user`。现有 `update_plan` 证明工具可以驱动结构化状态，AskTool 可按同样方式落地。

改动建议：

- `ProductionToolDispatcher.DispatchAsync` 增加 `ask_user`，参数为问题数组；同步等待回答，设置超时与取消。
- 工具结果返回结构化 JSON：已回答、已跳过、整卡拒绝。
- UI 复用输入区上方区域，不写入转录；回答后焦点回到输入框。
- 非交互环境返回明确“无法提问”，模型应改用普通文本询问。

风险：模型可能滥用提问打断流程。应在系统提示中限定“仅在关键歧义且无法从代码判断时使用”。

### 3. 原生失败重试（现在）

`NativeAgentLoop` 当前捕获异常后直接返回 Failed，没有重试预算；`ModelClientErrors.IsRetryable` 已有可重试分类，说明基础设施已存在。

改动建议：

- 在 `RequestModelAsync` 外层加重试策略：429 与可重试服务错误分开计预算。
- 复用同一条助手消息，不重复追加转录。
- 空响应重跑一次，第二次返回可重试错误。
- 中止立即生效；重试等待可被取消。
- 状态经 `SessionEvent.ActivityChanged(Retrying)` 暴露，UI 已有该状态。

这是原生内核最小、收益最高的健壮性补丁。

### 4. 队列项操作（现在）

本机已有队列与 steer，但 `InputViewModel` 明确说明：后端已接收的队列项，界面无法单条删除或改写。

改动建议：

- `NativeCSharpChatSession._queue` 增加按索引删除与提升为 steer 的方法。
- 新接口 `IQueuedPromptSession`，能力探测后 UI 才显示“删除/立即发送”。
- Pi 后端只支持整列清空，按能力降级，不伪造单条操作。
- 队列随会话持久化；中止不清空队列。

### 5. 统一全局搜索（现在）

`CommandPaletteViewModel` 注释写明“Global UI actions only”；设置页已有自己的搜索，且能跨层级匹配导航项。两者没有合流。

改动建议：

- 给命令面板增加数据源：全局动作、会话、页面、设置导航项。
- 结果分组显示；选中设置项时打开设置页并高亮。
- 保留禁用原因与快捷键展示。
- 不把输入框斜杠命令混入全局搜索，避免与扩展命令优先级冲突。

### 6. 通知收件箱对齐（现在）

`NotificationCenterViewModel` 已有收件箱、未读计数、待处理计数、丢弃提示与焦点感知。缺的是 PI 的“失败行优先、后台事件不导航、显式激活才跳转”等细节。

改动建议：

- 增加“只看失败/待处理”过滤。
- 后台会话完成只更新角标，不改变当前页与焦点。
- 明确横幅点击与收件箱行使用同一激活路径。
- 通知去重与清理保持幂等。

### 7. Plan 契约模式（近期）

本机已有 `PermissionMode.Plan`、`IExecutionModeSession`、`update_plan` 工具，缺的是“不可变计划产物 + 独立审批 + 执行绑定”。

改动建议：

- 增加 `submit_plan` 工具，写入项目内 `.fufucode/plan/<id>.md`，记录哈希、大小、创建时间。
- 审批卡展示标题、产物路径、执行模式、有效期；批准后原子切换模式并排队执行。
- 拒绝保留契约模式与产物，不删除用户内容。
- 不把 `PermissionMode.Plan` 与 `OperatingMode` 混成一个枚举。

### 8. 原生上下文压缩（近期）

这是原生内核最大的能力缺口。当前 `Compacting` 状态只由 Pi 的 `compaction_start/end` 事件驱动；原生内核没有压缩实现。

改动建议：

- 新增 Core 层 `ContextCompactor`：按预算摘要旧消息，保留最近窗口，生成检查点记录。
- 压缩不删除可见转录，只插入非交互分隔线。
- 手动 `/compact` 只在空闲时生效；自动压缩在回合边界执行。
- 提供商上下文溢出只做一次“压缩并重试”。
- 先做 token 估算与硬预算守卫，再做摘要质量优化。

工作量大，排在重试之后。

### 9. 会话级面板隔离（近期）

`WorkbenchLayoutState` 的保存 key 来自 `LayoutPreferenceKey() = "workbench:layout:v1:" + _layoutContext`，而 `_layoutContext` 是项目绝对路径。所以同项目多会话共用布局。

改动建议：

- key 改为“项目 + 会话”；首次迁移时复制项目布局作为会话初始值。
- 浏览器页签、文件页、变更页的选中项随会话切换。
- 终端仍按项目复用（当前 `_projectTerminals` 的设计合理），不要强行改成会话级。
- 后台回合只更新来源会话角标，不切换当前页。

### 10. 工作树会话生命周期（近期）

本机已有 `GitWorktreeService` 和“在新工作树中创建分支”动作，但缺少工作树会话的状态、同步、合并与冲突提示。

改动建议：

- 会话元数据记录工作树路径、分支、父分支、同步状态。
- 右栏 `变更` 页增加工作树分组：未合并、需同步、有冲突。
- 提供同步、合并、放弃三个显式动作；冲突时只显示文件与命令，不自动解决。
- 与自动开发的工作树生命周期共用同一 Git 原语，不复制实现。

### 11. 会话导入（近期）

本机持久化是 `PureAgentMessage` 的 JSON，另有 `SessionHistory` 与桌面元数据。导入需要适配不同来源格式。

改动建议：

- 先支持 Claude Code、Codex、Pi 三种最常见的 JSONL/JSON 结构。
- 导入时保留来源、原会话 ID、时间、模型与工具调用摘要；不导入凭据与未知附件。
- 每条导入生成来源标记；失败逐条报告，不产生半成品会话。
- 导入是只读操作，不修改来源文件。

### 12. 其余近期项

- **粘贴转文件 chip**：在输入区粘贴超过阈值时创建会话临时文件，点击展开回文本；不写入项目目录。
- **命令别名**：先做 `/new`、`/compact`、`/plan` 三个；内置别名优先于扩展命令，失败保留草稿。
- **会话状态机**：为每次运行分配 generation，旧响应不能写入新会话；切换会话时取消旧 UI 订阅。

## 后置与不接

### 子代理为什么后置

子代理是 PI-Desktop 最亮眼的能力，但对本机是**架构冲突项**：

- 本机自动开发已有派单、并发上限、隔离工作树、交付卡与审核闭环；再建一套聊天内子代理，会形成两套编排。
- `NativeAgentLoop` 当前是单会话单循环；子代理需要多实例、独立上下文、权限与模型，工作量 XL。
- 多代理会让审批、通知、队列、布局的复杂度同时上升。

如果要做，建议作为**统一委派层**：交互式子代理与自动开发共用同一个任务模型、同一个审批队列、同一个工作树生命周期。先做只读探索型子代理，再做写操作。也可以先以插件形式验证需求。

### 其他后置

- **Goal 模式**：依赖 Plan 的产物与审批地基；先做 Plan，再评估 Goal。
- **会话小地图、悬停卡、托盘、设置 IA**：体验项，成本低但收益有限，排在主链路之后。
- **远程 SSH、MCP/Skills/子代理管理页**：需要新的工作区提供者或扩展管理面，暂不进入近期。
- **Live Voice**：本机只有 TTS，实时语音需要外部账号与音频链路，与当前定位不符。
- **S3 配置同步**：无云端账号体系，安全与冲突成本高。
- **PI 插件运行时兼容**：会把 Node/Electron 带回默认包，直接否掉。
- **English-first i18n**：本机中文优先，不做方向性迁移。

## 风险与未验证

- PI-Desktop 为 0.21 早期预览，部分能力只有规格、未必稳定；本报告按规格评估，未运行验证。
- PI-Desktop 使用 LGPL v3；即使参考行为，也不应直接复制源码。建议按行为规格重写。
- 本机审批链路已核实到 `ExtensionUiDialogHost` 与 `NativeCSharpChatSession.RequestApprovalAsync`；但未在真实窗口中逐项验证 60 秒超时与无订阅者放行行为。
- 原生压缩、会话导入、跨后端队列操作均未实现，工作量评估基于源码结构，不是实测。
- 宏观评分含产品判断，不是纯客观测量；实施前仍需用户确认优先级。
