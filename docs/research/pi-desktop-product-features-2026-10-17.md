# PI-Desktop 本体功能研究与接入建议

日期：2026-10-17
调研对象：`vastsa/PI-Desktop` 的 README、`docs/guide`、`docs/spec/01-product`、`docs/spec/03-runtime`、`docs/spec/04-ux`、自动化与 Live Voice 规格
本机基线：`C:\Projects\Fucode\Fufucode` 当前 main

本文只研究 PI-Desktop 本体（不含插件市场），对照 Fufucode 现有原生能力，给出“值得学、值得接、不要照搬”的分级。未运行 PI-Desktop，未安装其依赖，结论来自公开规格与本机源码。

## 结论

PI-Desktop 真正值得学的不是 Electron/Rust 技术栈，而是四类产品契约：

1. **运行模式契约**：Agent / Plan / Goal 三种模式，Plan 和 Goal 提交不可变产物，再独立审批执行。
2. **会话级隔离**：每个会话独立保存面板页签、滚动位置、草稿、队列与运行状态；后台回合不抢焦点、不切换页面。
3. **人在环上的结构化交互**：权限卡、AskTool 问题卡、Plan/Goal 审批卡，都有明确的会话作用域、排队规则和过期语义。
4. **长会话可用性**：检查点分隔线、上下文检查器、会话小地图、提示队列、转向（steer）、失败恢复预算。

本机最值得优先补的 5 项：

| 优先 | 功能 | 本机现状 |
|---|---|---|
| P0 | Plan / Goal 契约模式 | 只有 `PermissionMode.Plan` 拦截写操作，没有计划产物、提交与审批闭环 |
| P0 | AskTool 结构化问题卡 | 没有 Agent 向用户提问的结构化工具 |
| P0 | 工具权限审批卡 | 原生内核直接执行变更工具，没有 allow-once / allow-session / deny 卡 |
| P1 | 会话级工作面板隔离 | 停靠布局按项目保存，不按会话保存页签与状态 |
| P1 | 子代理与委派页签 | 自动开发有派单，但聊天内没有 Task/TaskWait/TaskList/TaskStop |

## PI-Desktop 功能全景

### 工作区与导航

- 单窗口、单一当前目的地：Chat / Scheduled / Extensions / Settings。
- 左侧栏 275px，可在 240–520px 调整，低于 160px 折叠为图标栏；`Ctrl/Cmd+B` 切换。
- 左侧栏分区：独立会话、按路径分组的项目、项目会话、隔离 worktree 会话、底部设置/扩展/计划任务/通知。
- 右侧工作面板：页签、固定 `+`、`Ctrl/Cmd+J` 开关；每个会话独立保留打开状态、页签、活动页签与浏览器资源。
- 右侧面板支持临时预览模式：卸载主聊天、扩大面板，结束后恢复原布局。
- 全局搜索 `Ctrl/Cmd+K` 同时搜索会话、页面、设置行与命令。
- 目的地历史用 `Ctrl/Cmd+[` / `]` 线性前进后退，不显示常驻返回按钮。

### 会话与输入区

- 项目管理：打开本地文件夹、Git clone、远程主机；多文件夹项目，主根目录。
- 会话操作：新建、切换、恢复、分叉、导入、置顶、归档、删除、搜索。
- 输入区悬浮：空态居中，会话中底部停靠；模型与推理等级选择器在输入区内。
- 运行模式 chip：Agent / Plan / Goal。
- `@` 文件引用、`/` 斜杠命令、大段粘贴自动转为临时文件 chip、拖入文件成为引用 chip。
- 提示队列：FIFO 持久化，可删除、可立即发送；立即发送会升级为转向输入。
- `Alt/Option+Enter` 转向当前回合：不中断工具，下一次模型请求边界生效。
- 中止 `Ctrl/Cmd+.`：立即、幂等，取消待审批；未产生输出时恢复草稿。

### Agent 能力

- 内置工具：Read、Write、Edit、Glob、Grep、Bash、BrowserPreview。
- Plan 模式：只读研究 + 计划提交，写入 `.pi/plan/*.md` 不可变产物，独立审批后才进入执行。
- Goal 模式：提交目标与验收标准，写入 `.pi/goal/*.md`，批准后回到 Agent 模式执行并报告验证结果。
- 子代理：`Task` / `TaskWait` / `TaskList` / `TaskStop`，最多 16 个定义、10 并发；每个子代理独立上下文、模型、工具与权限；写操作子代理可用隔离 worktree；报告回传父会话，不把子代理完整转录塞进父上下文。
- 上下文管理：自动压缩阈值 90%；手动 `/compact`；检查点保留完整可见转录，只替换模型上下文；上下文检查器显示请求等待、响应、工具耗时。
- 失败恢复：429 静默重试预算、网络/超时/流错误独立预算、空响应重跑一次、上下文溢出压缩后重试一次。

### 权限与人工确认

- 三种决策：`allow-once`、`allow-session`、`deny`；没有 allow-always。
- 会话作用域：批准一个工具不会批准其他工具；每个会话独立自主级别。
- 权限卡内容：工具名、风险等级、简短原因、参数预览（可脱敏）、工作区上下文、三个动作。
- 每个普通会话最多一个待审批请求，因为 Agent 循环会暂停。
- 并行委派产生审批队列，只展示队首；按请求 ID 匹配，不按位置。
- 后台会话的审批不会抢焦点，也不改变当前会话。
- Plan/Goal 审批与普通工具权限分开；批准时绑定执行模式，有效期 30 分钟。

### AskTool 问题卡

- 位于输入区上方，与 Plan/Goal 审批同层，不进入转录历史。
- 支持单选、多选、自定义答案、跳过、下一题/提交、整卡拒绝。
- 每题 300 字符上限；Markdown 只用于展示，选项返回值使用规范化源文本。
- 长选项可滚动，头部与操作区固定；切换会话后重置到第一题。

### 扩展与系统

- Extensions 页只管已安装与市场；MCP、Skills、Subagents 独立管理，支持全局/项目作用域。
- 计划任务：Manual / Hourly / Daily / Weekly；保存项目、权限模式、模型、推理等级；运行历史 100 条；应用退出即停止，不做系统后台服务。
- Live Voice：可选实时语音，独立于 Agent 回合，不读工作区、不执行模型函数、不持久化转录；默认关闭。
- 配置同步：S3 加密保险库，只同步偏好与用户能力，不同步会话历史和源码。
- 远程主机：实验性 SSH 工作区。
- 托盘：Windows/Linux 可配置关闭到托盘；`Alt+Shift+W` 隐藏/恢复。
- 更新：启动 15 秒后检查，之后每 6 小时；稳定通道。

## 值得接入的分级清单

### P0：先补契约与安全，不是补 UI

**1. Plan / Goal 运行模式**

为什么值得学：它把“先规划再执行”从提示词约定变成可审计契约。计划与目标落成不可变 Markdown 产物，批准时绑定执行模式、权限和有效期。这个思路与本机自动开发的交付卡、验收卡天然契合。

建议实现：

- 会话增加 `OperatingMode = Agent | Plan | Goal`，与现有 `PermissionMode` 分开。前者决定工作流，后者决定工具权限。
- 新增 `submit_plan` / `submit_goal` 工具；提交时写入项目内 `.fufucode/plan/<id>.md` 或 `.fufucode/goal/<id>.md`，记录哈希、大小、创建时间与来源会话。
- 审批卡展示标题、产物路径、执行模式、有效期；批准后原子切换模式并排队执行。
- 拒绝保留契约模式与产物，不删除用户内容。
- Plan 模式禁止写入与插件工具；Goal 批准后回到 Agent 工具集。

验收：未批准不能执行；批准记录可读回；重启后待审批不自动重放。

**2. AskTool 结构化问题卡**

为什么值得学：澄清问题不再靠一大段自然语言，而是可回答、可跳过、可批量提交的结构化卡。它还能避免 Agent 在信息不足时猜。

建议实现：

- 新增原生工具 `ask_user`，参数为问题数组，每题含标题、单选/多选、选项、是否允许自定义。
- 卡片固定在输入区上方，不写入转录；回答作为工具结果返回。
- 每会话同时只允许一个待回答问题集；切换会话保留各自状态。
- 超过字符上限、空选项、重复 ID 直接返回校验错误，不生成卡。

验收：回答值可追溯；取消/跳过有明确结果；后台会话不会抢当前焦点。

**3. 工具权限审批卡**

为什么值得学：本机原生内核已有 `ExtensionUiRequest` 确认通道与 `ExtensionUiDialogHost` 弹窗，但仍是无风险分级的简单模态框，且 60 秒超时、无订阅者时自动放行。需要升级成可读、可审计的会话级审批。

建议实现：

- 决策：允许一次、本会话允许该工具、拒绝。不做永久允许。
- 卡片字段：工具名、风险等级、原因、参数预览、工作区、目标路径。
- 每会话一个待审批；并行子代理产生的审批进队列，只显示队首。
- 审批不自动过期；执行超时仍生效；重启后不重放旧审批。
- 高风险工具（删除、跨目录写入、命令执行）默认必须询问。
- 保留 CLI 的自动应答路径，但桌面端无订阅者时不得静默放行。

验收：拒绝后 Agent 收到明确拒绝而非超时；批准只作用于指定工具与会话。

### P1：结构性能力

**4. 会话级工作面板隔离**

PI-Desktop 每个会话保留自己的页签、活动页、浏览器资源、滚动位置、草稿与队列；后台事件只更新来源会话，不改变当前页面和焦点。

本机 `WorkbenchLayoutState` 按项目 key 保存（`workbench:layout:v1:<context>`），所以同一项目内的多个会话共用一套左右栏。建议：

- 布局保存 key 从“项目”细化为“项目 + 会话”。
- 浏览器页签、终端标签、文件页与变更页的选中项随会话切换。
- 后台回合完成时只更新来源会话的角标与通知，不自动切换当前页。
- 保持“面板不因工具写入自动弹出”，仍由用户显式打开。

**5. 子代理与委派页签**

本机自动开发已有派单、并发上限与工作树隔离，但聊天内没有交互式子代理。建议按 PI 的四工具模型实现，而不是再造一套编排：

- `task` 启动后台子代理，返回委派 ID。
- `task_wait` 收敛结果，设置默认与最大等待时间。
- `task_list` / `task_stop` 查看与终止。
- 子代理独立上下文、模型、工具与权限；只向父会话回传报告，不塞完整转录。
- 右侧新增“委派”页签，可查看子代理转录；子代理不能反过来驱动主 Agent。
- 写操作子代理默认使用隔离 worktree，并在页签显示合并/冲突状态。

**6. 提示队列与转向的完整 UX**

本机已有队列计数与 steer 文本恢复，但 `InputViewModel` 明确写着：后端已接收的队列项，界面无法单条改写或删除。建议补：

- 队列行支持删除、立即发送；立即发送升级为 steer。
- 队列随会话持久化，重启后恢复；中止不清空队列。
- 失败 steer 恢复到原会话草稿，不覆盖已有草稿。
- 队列项标明来源（用户输入、继续、计划任务）。

**7. 上下文检查点与检查器**

本机已有压缩逻辑。建议补 PI 的三点：

- 压缩不删除可见转录，只插入一条非交互检查点分隔线，显示消息数与估算 token。
- 自动压缩在回合边界执行，阈值可配置；手动 `/compact` 仅在空闲时生效。
- 上下文检查器显示请求等待、响应、工具耗时与累计 token。
- 提供商上下文溢出时只做一次“压缩并重试”，第二次明确报错。

**8. 统一全局搜索**

PI 的一个搜索框覆盖会话、页面、设置行与命令；本机命令面板只搜全局动作，设置页另有搜索框。建议：

- `Ctrl+K` 结果分四组：会话、页面、设置行、动作。
- 选中设置行直接打开设置页并高亮该行。
- 保留现有动作禁用原因显示。

**9. 会话导入**

本机已有 Claude Code、Codex、DSH、Pi、OMP 后端，但会话不能互相导入。PI 支持从 Claude Code、Codex、OpenCode、Pi 导入。建议先做只读导入与来源标记，再做格式转换：

- 导入时保留来源、原会话 ID、时间、模型与工具调用摘要。
- 不导入凭据、附件外链与未知工具结果。
- 导入失败逐条报告，不产生半成品会话。

**10. 失败恢复预算**

PI 的恢复策略值得照抄语义：

- 429 与普通可重试错误分开计预算。
- 空响应重跑一次，第二次显示可重试错误。
- 重试复用同一条助手消息，不重复刷屏。
- 结构化错误内联展示，toast 只用于连接、设置、更新、插件加载等系统事件。

### P2：体验打磨

- **会话小地图**：长转录右侧缩略轨，悬停放大并预览消息。
- **会话悬停卡**：500ms 后显示标题、模式、状态、模型、工作区、分支、更新时间。
- **托盘常驻**：关闭到托盘、运行/未读/置顶会话分组、`Alt+Shift+W` 显示隐藏。
- **大段粘贴转临时文件 chip**：超过阈值转为会话临时文件，点击可展开回可编辑文本。
- **设置信息架构**：偏好 / Agent / 工作区 / 系统分组，设置搜索覆盖每个字段。
- **远程 SSH 主机**：作为工作区来源，先做只读浏览与命令执行，再做完整编辑。
- **会话状态机与代际保护**：会话切换用 generation 防止旧响应写进新会话。

## 不建议照搬

- **Electron + Rust host-core + Node sidecar 三层架构**：本机纯 C# 原生内核已经成立，不应为了对齐 PI 重新引入 Node。
- **S3 配置同步**：涉及密钥、冲突合并与远端泄露面，当前收益低于成本。
- **Live Voice**：依赖 Codex/Gemini/OpenAI Realtime 账号与实时音频链路，本机当前只有 TTS，优先级低。
- **BrowserPreview 作为权限外的读工具**：本机已有 Browser Use 默认不装的边界，不能借 Plan 模式放开浏览器控制。
- **allow-always 权限**：PI 自己也刻意没做；本机不应先做。
- **把面板自动弹出当作工具反馈**：PI 明确“写入不自动开面板”，本机应保持用户显式打开。
- **完整 IDE 化**：PI 的非目标同样是本机的边界。

## 建议实施顺序

1. 先补权限审批卡与 AskTool。它们是安全与交互地基，后续 Plan/Goal 与子代理都要复用。
2. 再做 Plan/Goal 契约模式，接入现有自动开发的交付与验收记录。
3. 然后做会话级面板隔离与队列 UX，解决多会话并行的实际问题。
4. 子代理单独立项，先做只读探索型子代理，再做写操作与 worktree 合并。
5. 最后补搜索、小地图、托盘、会话导入等体验项。

## 未验证项

- 未构建或运行 PI-Desktop，未核对其实现与规格的差异。
- 本机“原生内核无审批卡”依据 `ProductionToolDispatcher` 当前实现；未逐条验证所有工具路径。
- 本机会话级布局未实现，依据 `WorkbenchLayoutState` 与 `_layoutContext` 的按项目保存逻辑。
- 子代理、会话导入、托盘、小地图均未在本机源码中找到等价实现。
- PI-Desktop 市场与插件相关结论见另一份报告 `pi-desktop-plugin-integration-2026-10-17.md`。
