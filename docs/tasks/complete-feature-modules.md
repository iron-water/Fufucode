# 任务书二：定时任务、插件与代码审查完整模块

日期：2026-10-10。状态：未开始。与任务书一共用外壳和动作，不复制设置状态。

## 使命与基线

把部分能力补成完整产品模块。已有一次性计划任务、本地 Pi 扩展管理及 Git 差异；没有独立审查模块。现有定时逻辑依赖应用运行、当前会话且空闲，不能称为后台调度。旧审查入口被移除，不能当作已实现。

## C1 定时任务

阶段一：完善一次性任务列表、编辑、启停、删除、到期处理、运行记录与错误恢复。任务明确绑定项目、会话、后端与时区；目标会话未打开时能由会话宿主处理，不偷换当前聊天。

阶段二：周期任务与后台执行。使用单一任务宿主，桌面窗口和手机仅提交控制请求。优先用户级后台进程，不默认安装系统服务或管理员常驻。提供明确退出/留后台选项，关窗后的行为可解释。

- 记录下一次时间、漏跑策略和每次运行身份；定义夏令时、时区变化、睡眠恢复、错过多次到期的行为。
- 保守默认：漏跑最多补一次；同任务不重叠；忙碌时等待，不自动中断用户任务；显式停止不被重试绕过。
- 持久化调度领取、提交与结果边界。无法证明外部操作未发生时显示待人工恢复，不声称任意工具执行恰好一次。
- 审批等待、后端缺失、登录失效和离线显示具体状态；调度不得绕过交互任务的审批策略。

验收：时钟可控测试覆盖周期与夏令时；实际进程覆盖关窗后台、重开、崩溃恢复、重复领取、睡眠/断网及停止；真实最低成本模型只跑必要闭环，所有试跑显式指定模型。任务记录与实际磁盘副作用一致。

## C2 插件管理

阶段一：补齐本地扩展来源、版本、启用范围、实际加载状态、安装/移除、更新与失败回退。沿用已有 pending/active 区分，不能把期望启用当成已加载。

阶段二：提供来源明确的目录和安装流程，支持固定版本、兼容性说明与更新记录。市场服务可后置，先用受控清单；不自动下载 latest。

- Pi/OMP各有适配和兼容标识，不能宣称全部扩展互通；统一界面不意味着统一运行格式。
- 外部连接器单独展示授权状态、所需访问与撤销入口；登录由用户完成，凭据不进入日志/导出。
- 明确插件是本地可执行代码；界面权限声明不能冒充操作系统沙箱。
- 更新失败保留可恢复旧版本与配置；正在使用时延后卸载，缺失路径或加载错误不阻断其他模块。

验收：实际扩展安装、加载、执行命令、禁用、重启、更新失败与卸载闭环；不支持后端/版本明确拒绝；授权撤销有效；同一插件状态在列表、设置和运行进程一致。

## C3 代码审查

阶段一：本地审查模块。用户明确选择工作区差异、暂存差异、提交或基准范围；审查快照保存仓库与提交身份，提交给选定后端。

- 输出发现项：优先级、文件、有效行位置、解释、证据及处理状态；区分风险判断和实际复现。
- 展示审查范围、基准、成本与运行状态；支持取消、过滤、跳转、复制及导出。
- 用户原有修改纳入明确选择的范围，但不能标成 Agent 本次修改。
- 文件变化后发现项标过时，不盲目沿用行号；默认只读，不自动修复或提交。
- 后续修复另起明确动作，选择发现项后展示范围并走现有执行与审批路径。

阶段二：PR读取与差异审查，支持已认证 gh；审查评论发布、PR变更、合并和推送必须有明确操作授权。身份包含仓库、PR和精确head，避免评论到旧差异。

验收：临时仓库包含已知缺陷与无缺陷样例，核对发现项位置和证据；取消/失败/变更过时状态正确；审查默认不写源码；真实后端完成最小审查闭环。模型不保证发现全部缺陷，不能用固定答案匹配宣称审查质量。

## 依赖、纪律与交付

后台调度依赖稳定的公共会话宿主；插件跨后端依赖能力表；审查依赖可靠 Git 范围选择与差异快照。OMP公共契约见总排期，不要求先重写全部Core。

核心宿主、调度与后端适配由主 agent 负责；列表/筛选/格式等受限任务可派单，注明允许文件与验收证据。测试首选免费 devin/swe-2，其他选择遵循当前成本纪律；强模型质量比较单独说明理由、预算并获同意。

每个阶段交付可用入口、构建/定向行为证据、失败恢复说明和更新后的记录；任一阶段尚未验收就保留进行中，不以菜单入口数量计算完成。外部授权/网络阻塞登记后继续其他模块。
