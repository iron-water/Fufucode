# CONV-AUTO：内置对话驱动开发、后台运行与自启

> 2026-10-15进一步明确：[CONV-AUTO-v4实施任务](conversation-workbench-v4.md)与[权威设计](../design/conversation-workbench-v4.md)为当前完整范围。此工作流取代原自动工作台设计，新项目默认自动；旧项目显式模式、暂停和授权状态保留。界面、迁移、持久通信、恢复与验收以v4为准。

日期：2026-10-15。用户要求把当前主控对话组织开发的方式做到Fufucode内，用程序取代仅靠提示词约定的流程。L4；复用现有自动工作台、AutomationStore、后台宿主与harness抽象，不另建竞争调度器或第二权威状态库。本文是待实施要求，不代表已验收。

## 产品闭环

用户选择项目，在主控对话提出目标、约束与授权；系统保存目标、工作包、依赖及验收。主控对话解释决定，程序负责创建工作树、启动/续接线程、跨线程通信、收取交付、审核/返工/集成和恢复。用户不需要复制prompt、催交卡、补发消息维持流程。

使用现有工作台原生线程图、收件箱与三模式：全人工不自主派单；半自动执行已批准动作；全自动在明确委托范围内持续推进。普通对话不等于无限授权，不能靠给所有待办自动点批准实现自主策略。

## 1. 工作树及执行身份

- 通过Git受控创建独立worktree，明确仓库、基线SHA、分支/HEAD、允许范围及继承改动。创建前记录意图，完成后保存真实路径；结果不明先对账，不重复创建、不清用户改动。
- 线程绑定harness、原生会话ID、模型/强度、工作树、任务/运行版本；同线程可顺序推进多个任务。并发须有独立写入范围，默认最多两个执行者；共享主线单写入集成。
- 使用统一harness层连接原生C#内核及Pi/OMP/DSH/Codex后端插件，按各自真实能力启停/观察/续接/输入/取消。不得依赖Codex桌面专属工具作为Fufucode自身运行前提。
- 创建工作树、启动模型会话、工具运行、提交及集成分别记录，回执不能互相替代。真实停写前不转交所有权。

## 2. 程序化消息与交付

- 消息/outbox与状态同数据库事务持久化，接收方按inbox/游标处理；发出、接收、处理、失败、未知分别记录。绑定project/thread/task/run/revision/HEAD及请求身份，按稳定ID去重。
- 交接卡仍由agent主动提供，但宿主负责捕获终态、验证交付并事务生成通知事件，不能仅依赖模型记得调用发消息工具。缺卡/坏卡/异常退出主动生成异常事件，不永久等待用户催促。
- 运行中协调、审批请求、执行停止、有效交付是不同事件。审核须验证执行轮次终态、自身及子写入者停止、实际HEAD与卡一致；提前消息只入待收状态。
- 主控处理接受/返工/等待/集成后继续推进；部分打回保其他有效成果。接受、实际集成、整项验收分离，重复事件不重复派工/工具副作用/整合。自然语言消息不自动获得高于原项目授权的权限。

## 3. 没有活跃执行者时自动判断下一步

项目无正在工作线程时触发本地对账，不直接启动模型。需要同时核实：仍有未满足目标；自动模式及委托允许；未被暂停/取消/接管；计划版本、预算、依赖、并发及写入权有效；在途消息/交付/进程身份已查清，避免失联任务被重复派发。

有待审交付先审核；有原任务待修复先续接；有明确可运行任务再派。缺计划才按需唤醒主控规划，不为维持忙碌制造任务。全部受阻就记录原因、责任方与恢复条件，继续独立项；目标均满足后真实项目验收，不能因全部线程idle认定完成。

新目标/批准、消息到达、执行终态、审核/集成结果、依赖解锁及恢复事件推动去重协调。CORE是可恢复状态机，M仅在需语义判断时调用，不把提示词约定当唯一运行保障。

## 4. 唤醒与补漏

用户允许每小时唤醒；实现每项目可配置本地补扫，默认每小时只做确定性对账。有新的待处理事件或有权推进的未完成任务才触发协调/M，无变化不请求模型。即时事件与定时补扫使用同一去重入口。

事件闭环可靠后可关闭周期补扫，但保留宿主启动/恢复及执行终态的必要对账。不能把“关闭定时”变成丢交付。此为Fufucode内置能力，不修改当前开发Fufucode所用的Codex两小时heartbeat，不给提问/执行会话增加定时任务。

## 5. 完全后台与开机启动

- 独立用户级后台宿主持有项目及受管执行会话，GUI仅观察/控制；关闭窗口、托盘、暂停调度、停止后台与退出程序有明确不同语义。关闭窗口后按用户选择继续已授权任务，不依赖窗口存活。
- 设置提供“关闭窗口后继续后台运行”“开机自启动后台”、后台状态及停止入口。保守采用当前用户登录后启动，明确与登录前系统服务的区别；开发此能力不等于修改当前机器启动项。
- 自启/手动启动均单实例；无窗口启动后台，桌面重开连接同一宿主。关闭自启/卸载/失败回滚只处理本产品登记，保留其他项目与用户状态。
- 断电/崩溃/睡眠恢复先核实持久任务、消息和真实进程，未知副作用不重放；继承暂停/模式/授权/预算。电脑关机或未登录不承诺执行，凭据不可用如实等待。

## 6. 验收与派工

M先确定真实接口、起点、文件占用与允许范围，按完整垂直包实施；共享组合根/设置/发布由M持有，不另做仅动画HTML。实现模型按L4与成本明确选择，测试/试跑lead显式最低成本可用模型。

实际证据须覆盖：对话目标→真实工作树/会话→消息/成果→审核/原会话返工→整合/依赖解锁→继续或最终验收；以及缺卡/异常退出、重复事件、丢回执、空闲未完成续推、人工暂停/全人工不自启、预算耗尽/全部阻塞、关窗后台继续、后台崩溃/登录自启恢复、重复启动及关闭自启。夹具、真实模型闭环和安装环境分开验，不用类存在/编译通过宣称全自动已完成。

主动交付实现、运行入口、命令/证据、版本、未验与接线情况，沿既有用户授权回传管理线程。本文由提问线程补要求；M在唯一main租约下收编并推进产品，不竞争主线提交或改动真实开机配置。
