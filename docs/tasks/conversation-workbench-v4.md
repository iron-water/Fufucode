日期：2026-10-15。用户明确要求：对照Codex实践研究缺口，以对话组织的自动工作流取代旧自动工作台默认设计，并重做匹配的控制监控页面。L4大改，M统一架构/共享接线/集成，最多两个执行者；不改当前外部Codex监督任务或本机开机项。

## 不可降级的范围

新项目默认自动，用户主控对话交目标即可在委托内连续开发。程序控制真实worktree、执行会话与消息、自动收交付、原线程修复、审核集成与空闲续推；GUI可关闭，宿主可恢复，登录自启可配置。缺任一项不宣称替换完成。

旧人工/半自动保留为接管选项，不再是新入口默认；已有项目模式/暂停/会话/成果必须保持。不能只删Automatic异常、把枚举改默认或自动点所有审核按钮。

## 两个纵向包与并行边界

| 包 | 目标和真实出口 | 责任 |
| --- | --- | --- |
| AUTO-LOOP | 一项目对话目标→计划/有效委托→真实worktree与worker→缺卡/终态接收→持久消息/去重协调→M审核/原会话修复→实际候选集成→下一任务；含暂停/双事件/M忙 | M持有Core共享事务/宿主/原生工具桥，限定独立模块可派实现者；必须能在产品中跑，不依赖Codex应用工具 |
| AUTO-OPERATE | 新原生总览/线程/成果/活动/设置界面接AUTO-LOOP真实投影，两个worker/跨插件能力、预算与上下文、后台/登录自启/恢复及迁移 | 投影冻结后独立UI可并行；M持有组合根、设置、包布局、旧调度切换和总体验收 |

不是把数据库、桩、动画拆成无数可单独“通过”的节点。每个包必须有可运行入口与完整用户路径。M开工前明确实际允许文件、活动写入者和真实起点；执行者不擅自扩Core范围/改其他任务的共享UI。

## 验收矩阵

| 场景 | 必须观察到 |
| --- | --- |
| 干净新项目 | 默认自动，填写目标/委托后真实建树和线程，后台记录身份与动作回执 |
| 目标未给/后端缺失 | 明确待目标/需配置，无模型空转，不假回显 |
| 正常两包+依赖 | 独立可并发、有依赖等待实际集成/验证后解锁 |
| 缺卡/坏卡/异常退出 | 程序产生异常事件并形成可处理任务，不等待模型send或用户继续 |
| M忙+多交付 | 同项目仅一M决策，事件积压可见且合并处理，不丢消息、不另开第二M |
| 丢回执/重复终态 | 查询原意图/回执，不重复worktree、工具、副作用或集成 |
| 修复/接口冲突 | 先归因，原线程局部返工保兄弟部分，公共写入者明确 |
| idle但未完成 | 给出下一步或具体阻塞，有条件才续推；暂停/人工/全阻塞不误派 |
| 预算/权限 | 达限停止新付费动作，有效在途处理按委托；越权不因自动模式放行 |
| GUI断开/关闭 | 后台任务继续，GUI重连同宿主恢复游标/草稿，无第二执行者 |
| 重启/登录自启 | 身份/消息/工作树对账，未知副作用不重放，暂停项目不自动复活 |
| 旧状态迁移 | 原身份/有效接受/集成/暂停保留，无新旧双调度或静默换后端 |
| 最终验收 | 目标版本+候选SHA+独立行为证据一致，全部idle或unit绿不等同完成 |
| UI | 四工作页真实操作、800×640/IME/返回/DPI/脱机/控制范围和状态文本准确 |

模型测试lead/真实probe显式devin/swe-2或最低成本可用替代。普通本地无模型编译不涉及模型参数；纯样稿不用模型请求。按影响做定向构建/行为检查，阶段里程碑集中全量与安装闭环，不频繁冗余回归，不放宽断言。
