本文件冻结产品边界和交付责任；实际C#接口由D1/D5结合源码确定，不凭规划虚构协议。

用户当前采用一任务一执行会话、主会话整合的模式。开工、范围/依赖协调、交付和主会话验收后操作卡遵循 [AI会话执行与交接协议](session-handoff-protocol.md)。所有执行会话在独立工作树实施，不因历史prompt绝对路径回到主区；主会话M负责共享接线与最终整项验收。协调/收编后M必须输出可直接转发的修复或下一项完整prompt，不要求用户自行推断或拼接。

上述为当前CLI任务执行约定。用户新增U产品形态要求“线程为图节点、线程内多个任务、按交付部分打回”，以[U任务契约](automation-workbench.md)为准；旧一任务一会话不限制新产品Thread/Task基数。现有运行不迁移、不接管，新增适配须版本化验证，固定会话唯一写入约束不变。

## 产品与接口边界

新增 U 自动开发遵循 [产品任务书](automation-workbench.md)：功能区侧边栏的单个 tab，以开发流程图及事件动画为中心；任务、交付、决定与恢复从相应节点进入，不复刻整套应用前端。交付/审核/集成分别持久化，跨 harness 任务使用官方适配器，打回保留原身份；UI 只发带身份的命令，不成为第二会话写入者。U1 独立规则先行，U2 依赖 G1/D5、生命周期验收归 G2；动画暂停与后台停止分开。

- 保留Avalonia五区、Windows设置式导航和已完成辅助栏。新模块接入通用容器，不复制业务外壳。
- Pi/OMP使用官方引擎，能力以实际版本验证；创建后固定BackendId，旧会话默认Pi，不做运行中切换或跨后端历史转换。
- 公共会话契约包含身份、生命周期、消息/工具、发送/停止、审批、恢复、能力和错误；UI不拼后端RPC。prompt接收不等于任务完成。
- 公共后台宿主是唯一会话写入者；桌面、调度、手机通过命令与事件使用它，不另起同会话写入进程。须有命令身份、快照/事件补齐、有效审批与释放/恢复。
- 快捷键沿用公共动作ID/范围/可用性，不另建每页一套判断；实际动作目录是权威。
- Git审查输入包含仓库、基准/目标、文件状态与固定差异快照；不能将全部差异归因Agent，不沿用变动文件旧行号。
- 资料/产物包含稳定ID、来源、引用或副本、版本、实际路径、提取/索引状态；删除条目不默认删除源文件，默认不上传整个库。
- 浏览器工具共用profile/tab、导航/权限/操作与观察结果，两后端不分别建宿主，网页不获得任意本机对象。
- 手机首版只控制会话，先局域网；图像先一种真实供应商；资料先本地全文；插件先本地生命周期；审查先本地差异。
- 皮肤先Fluent基线与Metro/Material样稿，Luna/Aero首轮后，Liquid Glass暂缓。公开部署、收费采购、登录和系统修复不在默认授权中。

D1将实际接口和能力表记录docs/records/D1-backends.md，D5记录docs/records/D5-host.md。依赖方只按交付契约真实接线；未确定接口可做独立原型，不把夹具当产品完成。接口改变同步调用方和记录，不做无需要的全仓抽象。

## 文件所有权

Codex为集成负责人；OMP为受限任务执行方。开工先核对实际文件，以下Features目录是新模块建议，不假设已经存在。

| 文件范围 | 写入责任 |
| --- | --- |
| src/Fufucode.Pi/**、Core现有会话/持久化/元数据/设置/工作树、extensions/fufucode-bridge/** | Codex D1/D4/D5核心，按任务顺序持有 |
| App/Integration/**、MainWindow*、Program、AppOptions、公共动作/SettingsPage与项目引用 | Codex唯一共享集成入口 |
| BrowserView*、Infrastructure/Browser/** | Codex D3之后D8 |
| ConPtyTerminalSession、TerminalBuffer、TerminalScreenControl、TerminalDockView*与TerminalDockViewModel | Codex D2 |
| ExtensionsPage*、ExtensionsPageViewModel | OMP O5；Integration交Codex |
| App/Features/Shortcuts、Storage、Library、Review、Schedules、Images各独立目录 | OMP对应任务，不扩大到共享外壳 |
| Core新模块文件 | Codex明确路径后交对应任务，不默认开放Core全目录 |
| docs/frontend-prototype/skins、mobile | OMP S1/M0原型，不改生产外壳 |
| Styles、WorkbenchAppearance与共享控件 | Codex S2/S3，避免与共享UI任务同时写 |
| 正式手机/远控服务 | Codex D6根据D5确定目录；非核心页面可另派OMP |
| packaging、发布物、全量自测注册入口、权威计划/进度/决策 | Codex集成，执行测试仍用最低成本模型 |
| docs/records/任务ID-*.md、独立定向测试 | 对应任务负责人 |

共享main同时最多一个源码写入lead。真正并行开发用受限临时worktree，Codex收编；原型/文档可在非重叠目录同工作区并行。不要让用户独立启动的两位lead同时集成main。原有用户文件保护，reference只读，不push、不改写历史，不直接递归删除worktree。

范围不足时记录待集成补丁或由Codex明确扩展任务范围；不擅改另一任务在写的文件，也不为普通可逆选择反复等确认。独立模块未接共享入口不能报整项可用。

## 阶段验收门

| 门 | 通过条件 | 解锁 |
| --- | --- | --- |
| G0 | 边界、详细图、prompt和三类任务书一致，路径/链接有效 | D0/D1及独立OMP任务 |
| G1 | Pi/OMP分别真实创建/对话/停止/审批/恢复；身份/能力准确，旧Pi数据保持 | 依赖后端的插件/审查、后台宿主 |
| G2 | 唯一宿主、关窗/重开/崩溃恢复、事件补齐和有效审批真实通过 | 手机接线与定时后台 |
| G3 | 首轮各项行为/原生验证，集成全量、迁移、包内和干净安装闭环通过 | 首轮稳定版本与高级能力 |

G1/G2前依赖任务可做非依赖原型/规则/页面，真实接线不得越门。外部条件阻塞记录后继续独立任务，验收门仍保留未通过。旧记录不得直接当本轮验证证据。

## 贯穿任务与交付

每个任务和主会话的难度标签按 [会话难度与派工提示](session-difficulty.md)。新任务综合评估难度并给具体模型建议；打回保留原主模型，仅比原始派工升高至少两级时提示更强子代理辅助，不自动派发。完整prompt首行保留等级；测试/验证/试跑仍最低成本。

新派推荐主模型及备选必须写当前canonical目录中的完整`group/`模型ID；推荐主模型直接放入prompt首行，不能只给档位或简称。

- Q：每项必要构建/定向验证、错误恢复、数据迁移、诊断/费用/凭据边界、记录和小步提交；文案不反复全量回归。
- V：Codex逐项computer-use验证新构建的原生指针/键盘/输入法/焦点/DPI/返回路径，不到最后攒一起。手机要求真机，桌面窄窗不算。
- S：OMP持续做样稿；Codex分段接入主题与原生验证。等待用户选风格时其他线继续。
- P：发布环境收尾贯穿；环境故障不阻塞实现，最终G3不能缺干净安装证据。
- 每项交付实现、实际命令/结果/证据、未验证项、提交和下一步。新缺陷登记failure-registry；静态核对/回调/原生交互分别报告。
- 执行模型在任务收尾时主动生成完整交付卡，写入本任务记录并在最终回复展示；包括修复后的重新交付与部分/阻塞交付。不依赖用户催发或填写，字段按session-handoff-protocol。需协调时主动给协调卡，M处理后主动给下一步操作卡。
- 模型测试显式最低成本可用模型，首选devin/swe-2；不可用记录后选最低成本替代，强模型验证需理由/预算/同意。普通编译和无模型测试不需要模型参数。
- 不预估未经校准的工期/token。首轮最长依赖通常D1→D5→D6→G3；浏览器原生问题可能形成另一条主线。
