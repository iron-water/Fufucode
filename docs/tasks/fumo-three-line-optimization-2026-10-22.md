# FUMO 三线优化：证据驱动的重新设计

## 研究结论（决定改法）

| 来源 | 结论 | 对本项目的直接含义 |
|---|---|---|
| SWE-agent ACI (arXiv 2405.15793, NeurIPS 2024) | 同一模型换 ACI 后 SWE-bench 12.5% pass@1；编辑工具带 linter 在写盘前拒绝非法编辑；文件查看窗口约 100 行；搜索输出刻意精简；空结果要显式反馈 | 编辑要有写盘前守卫；读取要有窗口与续读；空结果必须显式说明 |
| Anthropic《Writing effective tools for agents》(2025-09-11) | 工具数量不是越多越好，应合并重叠工具；响应要 token 高效（简洁/详细两档，72 vs 206 tokens）；截断信息要可操作；评估要同时看准确率、耗时、工具调用数、token、工具错误 | 描述要写清"何时用/何时不用"；截断提示要给出下一步 |
| Anthropic《Building effective agents》附录 | 避免让模型数行号/做重转义；参数设计要让错误难以发生 | 行号由工具输出，不让模型自己数 |
| Compaction 研究（Governance Decay；Lost in Compaction/COMPINT；CompactBench；Factory 36,611 消息研究） | 压缩后约束遵守率可从 0% 升到 30–59%；"Constraint Pinning" 可恢复到 0%；drop-oldest 对早期事实召回为 0%；评估必须检查已改文件、失败方案、用户约束 | 原始任务陈述必须逐字保留；要有确定性状态台账；要测多轮压缩后的召回 |

## 已确认的两个真实缺口

1. `faster` 档位从未被重复实测，只有协议层断言"不声明嵌套"。
2. 压缩只断言"摘要存在"，没有断言"跨多轮压缩后早期约束仍可召回"，也没有覆盖重复压缩。

## 执行计划

### A. 工具（ACI）

- A1. 重写 8 个内置工具描述：每个写清用途、何时用、何时不用、返回形状、边界。证据：Anthropic 要求"像写给新同事"、声明局限性。
- A2. `grep_search` / `glob_files` 截断提示改为可操作：给出收窄方式（加 glob、缩 path、降 max_matches）。
- A3. 写盘前守卫（SWE-agent linter 对应）：`edit_file` / `write_file` 对 `.json` 目标校验解析结果，非法则拒绝写盘并说明位置；`.cs` 无廉价解析器，不做伪校验。
- A4. 工具调用效率实测：同一任务记录工具调用数、失败数、token；对比描述改写前后。

### B. 压缩

- B1. 确定性状态台账：从历史中提取已改文件、执行过的命令与退出码、失败工具、验证状态，作为独立消息固定保留。
- B2. 多轮压缩稳定性：连续两次压缩后，原始任务陈述仍必须存在；补测试。
- B3. 约束召回实测：构造埋有硬约束的长会话，触发压缩后让真实模型回答依赖该约束的问题，重复 N 次统计召回率。

### C. Subagent

- C1. 实现文档承诺但未实现的 per-run 读取缓存（read_file/grep/glob/list 去重），减少重复落盘与重复扫描。
- C2. faster 与 stronger 各跑 N≥3 次，两种任务（事实定位、五子系统调查），记录命中率、工具数、嵌套次数、token、耗时，取中位数与范围。
- C3. 结论必须基于重复实验；若 stronger 仍无收益，明确写"当前规模下不成立"，不粉饰。

### D. 验证

- D1. 单元/协议测试覆盖每一项新行为（含 faster 档位与多轮压缩）。
- D2. 解决方案全量构建 + Backend/Core/Performance 三套测试。
- D3. 真实网关重复实验，输出原始数据。

## 验收标准

- 所有新行为有可失败的测试（不是只断言"不抛异常"）。
- faster/stronger 各有 ≥3 次真实运行数据。
- 压缩在 ≥2 轮后原始约束仍存在，且有真实模型召回数据。
- 未通过的项如实标注，不写成通过。
