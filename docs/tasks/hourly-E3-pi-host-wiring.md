## 执行顺序

1. 从本机固定 Pi 版本源码和现有安全重启链核对事实：精确版本取实际 CLI 所属包，OMP 会话不冒充 Pi；`get_state` 无加载清单，`get_commands` 仅命令，现有 ActiveExtensionPaths 不能凭名称当完整加载快照。
2. 先做自有临时插件的无云最小加载证明，决定现有官方扩展/桥能力是否能提供“固定入口成功初始化”的事实及错误关联。若使用包装入口/证明命令，须区分真实原入口、托管副本、包装产物与引擎回执，按请求身份/固定版本/精确路径绑定；不得把自身哨兵存在等同于原插件初始化完成。失败/超时/身份不匹配保持 unknown，不新增虚构 RPC，不改写第三方运行时。
3. 再接 ILocalPluginHost：真实活动状态、信任、草稿/原 sessionID/后台活动守卫；用户明确的安全重启必须复用现有链，正在生成/排队/重启/切项目不能偷偷结束任务。pending 只登记，不自动重启或调用模型。处理 E3 服务对活动版本应用只登记 pending 的现有约束，不能以伪造空快照绕过；设计明确且可验证的安全释放/恢复阶段或新的显式安全请求协议。
4. 实际应用失败后检查真实旧会话/配置/目录，不能只凭选定字段没变化称回滚。晚到回执必须仍属于原 token/version/project/host，项目切换后不得修改新会话。持久 in-flight 的显式释放只能在证明无未来副作用后进行。
5. 在原扩展页增量增加必要的显式安全应用入口及状态说明。支持关闭/恢复/启动失败态的离线目录路径；现有返回路径、选择器取消与版本列表保持可用。没有完整真实宿主能力就保持禁用并解释原因。
