# 节点人类变更卡

2026-10-11用户新增要求：点击对话线程内某一步开发进度，提交元数据给固定M；可追加验收要求，也可停止当前工作后发送修订提示词。所有变更必须落盘。

## 当前能力与缺口

当前agent-task-control支持Revoke、Update、Rebuild；精确停止受管agent、围栏旧run、新版本任务及依赖重映射、原工作树/会话/交付历史保留、commandId去重和M忙时排队。Update/Rebuild创建新的任务身份与工作树，不是原会话即时注入提示词。当前CLI运行仍为整项交付，尚无正式stepId/partId的审核映射。

已实现节点变更表单、提示词模板、人类意见收件箱、M确认记录、审核需求版本绑定及过期决定阻断。原固定免费测试M实测：同交付先accept，追加要求并确认revision=1后rework，旧决定保留、重放零调用。证据记录见M-human-core-2026-10-11.md。

用户明确暂不做“停止后直接向原保存会话发送新要求”。当前停止、撤销及带新promptFile创建任务版本仍走原控制入口。stepId/partId为要求定位元数据，v1仍整项审核；不能把标签说成局部协议已完成。

## 控制边界

固定M仍是唯一审核/集成负责人。不默认增加有裁决权的第二总控。人类意见入口仅收集、验证身份、持久化及排队；如以后增加转达agent，其职责限于整理，不能批准、集成或覆盖用户原文。

1. 追加验收：不中断执行；持久化新的要求版本，M确认适用范围后，下一次审核绑定该版本。若审核已投递，标记当前审核需求过期，禁止旧结论自动接受/集成；等待原投递终态并核对，不重发状态不明投递。
2. 停止并修订：先持久化意图，再围栏目标task/run，核对受管进程身份后停止；等待agent及worker实际停止、核对HEAD/继承改动。M检查新范围与依赖，批准新任务版本。可恢复原会话时须使用原模型/原worktree/原session；否则明确显示新版本重建，不能伪装为原会话续接。
3. UI选中线程及步骤不是执行授权。当前v1只能映射明确的taskId；未映射stepId不得把整个线程静默停掉。多任务线程停止必须明确列出受影响任务，并按新版协议逐项执行。
4. 已集成代码不因意见变更而自动回滚，后续修订是独立任务。门禁、外部权限及成本规则不能通过意见卡绕过。

## 元数据模板

```json
{
  "schemaVersion": 1,
  "type": "human.change.request",
  "commandId": "唯一且可重放的命令ID",
  "projectId": "当前项目ID",
  "threadId": "原生线程ID或待派发身份",
  "taskId": "当前任务ID",
  "stepId": null,
  "partId": null,
  "runId": "当前运行ID，未运行则null",
  "baseRevision": "当前需求版本",
  "baseHead": "提交时核对的HEAD，未运行则null",
  "action": "append_acceptance或stop_and_revise",
  "requirement": "用户新要求原文",
  "acceptance": ["可验证的验收条件"],
  "retain": ["必须保留的行为或产物"],
  "scopeChanges": [],
  "createdAt": "UTC时间"
}
```

当前CLI实现：tmp/agent-flow/human/task-任务ID.json为权威索引，request-commandId.json为不可变正文，ack-commandId.json为M适用性决定，dispatch-commandId.json为模型运输记录。queued不等于已确认；applied只表示M确认适用要求，不是产品已通过。supersedes显式替代原要求但保留全部历史，阻塞要求可经新变更纠正。相同commandId不同正文拒绝，投递不明不自动重发。

版本审核事件保留原05.json，并追加05-rN.json及review-rN.json。Review入口持有需求锁检查当前版本，集成入口也检查版本并与提交新要求互斥。集成期间提交会明确报忙，不能悄悄修改正在提交的验收标准。新任务版本继承人类要求；已集成任务须创建新版本，不回写历史。

## 停止后修订提示词模板

```text
模型：沿用本任务原模型；任务：{taskId}；需求版本：{revision}。
本次只修订 {stepId/partId或明确的整项任务}。
变更卡：{已落盘路径/commandId}；原runId：{runId}；基准HEAD：{HEAD}。
新增要求：{用户原文}
验收条件：{逐项列出}
必须保留：{已接受部分、兼容行为及用户继承改动}
允许修改：{M批准的准确路径}
继续在已核实的原worktree/保存session工作；发现身份或HEAD不一致先交协调卡。
不自行扩大范围、不回滚已集成历史、不切换模型、不派新任务。
完成后提交真实交付及验证证据，绑定本次需求版本，等待M审核。
```

## 实施验收

先在独立临时仓库以显式devin/swe-2验证追加要求改变审核结果、审核途中需求改变拒绝过期accept、停止并原会话修订、重复点击无第二次执行、崩溃恢复及意见/决定/交付完整落盘；再启用生产入口。不得拿真实生产任务做破坏性测试。
