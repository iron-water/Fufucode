# 原生 C# Agent Runtime：真正摆脱 Node 依赖

日期：2026-10-15。用户核验报告中的“C4全C#执行内核”，目标是无需Node即可使用真实Agent。此任务ID使用NATIVE-CS，避免与旧hourly-C4-vertical半自动调度闭环混淆。

## 当前事实与目标

### 2026-10-15用户明确的最终范围（优先于下文阶段闭环）

- 最新分发定位：作为Fufucode原生内核随主程序默认安装、新安装默认选择。Pi/OMP/DSH/Codex转为默认启用的后端插件，Browser Use/电脑操控默认不安装、到设置一级“插件市场”按需安装。安装/启用/运行时与迁移约定以 [插件市场任务](native-kernel-plugin-marketplace.md) 为准；四后端插件缺失不能阻碍原生模式。

- 交付与现有Pi、OMP、DSH、Codex同等级、可替代当前生产路径的完整原生C# Agent内核，不以最小聊天/工具演示或“以后补高级能力”作为本任务完成。
- 作为第五个后端，必须通过现有通用harness/engine抽象接入。前端、桌面/后台宿主、移动端、调度与工作台通过统一契约使用它，不为C#另造绕过抽象的专用路径，也不使其他四后端成为其运行时依赖。
- 对照四后端当前真实能力及产品需求，建立逐项能力/行为验收矩阵：模型与流式事件、上下文管理、工具及权限审批、发送/steering/follow-up/停止、会话持久化恢复、MCP/技能/扩展、子代理/后台任务，以及工作台、终端/浏览器等产品工具接入。四后端差异须显式映射，不能把既有抽象缺口或虚假徽标切换当作真实兼容；用户要求的替代能力有缺项就保持未完成。
- GitHub项目仅为实现参考。先依Fufucode抽象契约设计内核，参考适用实现；不得直接选一个外部Runtime接壳后就宣布等价。引入具体代码/依赖需说明适配和许可，不能反过来迁就其UI或协议。
- 使用实施时最新正式发布的.NET与匹配稳定SDK/包；开工核实微软正式发布与本机SDK，记录固定版本。预览版不默认为正式版，不凭“最新”长期浮动依赖。
- 下文“最低真实闭环”仅为第一道开发验证门，不能替代上述完整生产验收。最终必须证明无Node的生产路径、统一抽象接入、能力矩阵及部署/恢复行为均达标。

PureCSharpAgentEngine.cs已有C#接口和单轮协调，但默认客户端只回显用户输入。未发现真实IPureModelClient供应商实现或生产IPureToolDispatcher实现、桌面接入；RealSessionBootstrap仍定位runtime/node/node.exe与Pi cli.js。不得以此声明Node已移除。

目标是在不安装/打包/启动Node、Python或外部Agent CLI的条件下，C# Runtime真实处理模型请求、上下文、工具循环、流式事件、审批/取消、会话持久化恢复，接入桌面实际发送路径。可选Pi/OMP等后端可保留自身依赖，但不能成为原生C#模式的启动前提。用户显式调用某项工具所需外部程序与Agent自身运行时依赖分开说明，不伪称所有外部工具均无依赖。

## 最低真实闭环

1. C#模型客户端向实际可配置供应商发送请求并消费流式响应/工具调用；正确处理错误与取消，缺配置明确报错，不以回显伪装模型。
2. 工具schema、调用ID、参数与结果、审批/拒绝、文件范围和取消真实执行；工具结果回填上下文并再次请求模型，直到最终回复或有界停止，不能只调用一次后返回。
3. 保存并恢复真实消息/工具状态和会话身份，避免仅计数；停止/重开后不重复有副作用的工具。后端身份与已有历史迁移边界明确。
4. NativeCSharp作为实际可选引擎接入注册表、配置、桌面会话创建与流式时间线；原有Pi/OMP/Codex/DSH不被一个徽标切换假装替换。
5. 测试分层：纯本地协议夹具/确定性工具验证机制；显式最低成本模型验证真实请求→真实受限工具→结果回填→最终回复。夹具与真实模型证据分别记。
6. 构建Node-free分发候选，在没有Node/Python/Pi/外部AgentCLI的隔离环境验证启动、创建、发送、工具、审批、取消、恢复；检查运行进程树与包内依赖。只改PATH或只看当前类没有Process.Start，不能证明产品整体无Node。
