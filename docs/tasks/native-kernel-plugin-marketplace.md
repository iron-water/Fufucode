# 原生内核默认安装与插件市场

日期：2026-10-15。用户最新产品决定，取代四后端均为不可分离内置能力的旧安排。状态：需求已更新，产品尚未按此重构验收。

## 原生内核与默认策略

- 正在开发的完整C# Agent Runtime定位为Fufucode原生内核，随主程序默认安装，新安装默认选择；保持与其他后端相同抽象契约，不绕过公共harness层。采用实施时最新正式.NET。
- Pi、OMP、DSH、Codex改为四个后端插件。用户原文“默认作为插件启用”：保守按四后端插件默认安装并启用处理，不擅自改成四个都不安装；默认启用不等于抢占原生默认后端、自动运行、登录或发模型请求。模型/凭据/插件运行时缺失须给可操作状态，不假称可用。
- 原生主程序启动与原生任务不得依赖四插件或其Node/Python/外部AgentCLI。后端插件运行时归插件依赖部署管理，可独立安装/修复/卸载，不能重新作为基础安装器全局硬门槛。打包明确区分原生核心包与默认插件包及其大小、来源、依赖；四默认插件不能卸载时破坏核心。
- 浏览器控制（Agent Browser Use/CDP）与电脑操控作为可选功能插件，默认不安装、不启用，经市场显式安装后提供能力。普通内置浏览器/文件预览不自动视为浏览器控制插件，也不因控制插件未安装而删除普通浏览界面；是否进一步拆普通浏览器由M列明范围，不擅自扩大。
- 其他非必需功能采用按需安装方向；M先列模块清单及默认策略，避免未经清单把持久化/权限/基础文件操作等核心支撑也拆到不可用。安装/启用/配置完成/运行中/授权是不同状态。

## 设置一级菜单：插件市场

在现有设置页增加一级“插件市场”，沿用已完成Windows设置式导航，不另造全应用外壳。包括插件目录、搜索/分类、详情/版本/兼容/依赖、安装进度、启用/禁用、更新/回退、卸载/修复、错误与权限说明；不安装的功能显示真实未安装与安装入口，不能渲染假开关。

统一管理后端插件与功能插件，明确能力声明/版本契约/配置/工具注册/卸载恢复。复用已有插件生命周期代码，区分引擎自身扩展与Fufucode产品插件，不把Pi扩展安装器改名冒充统一市场。市场首版可使用受控本地目录/明确来源包，不要求先部署公网商店；不能用假目录冒充可下载安装。

## 生命周期、兼容与验收

1. 在途会话/工具依赖插件时不得直接卸载或静默换后端；给出停用/安全停止/稍后操作路径。历史会话保留真实backendId/插件版本与数据，缺插件时可安装恢复，不能映射成原生后端伪称上下文兼容。
2. 浏览器控制/电脑操控安装后才注册工具，启用与使用权限分开；卸载后撤销注册、句柄/子进程/连接，保用户数据与原浏览页面，不留可调用幽灵工具。插件不得绕过统一审批。
3. 安装包内容/兼容/依赖与失败回滚明确；卸载用户数据保留规则、包来源/完整性及权限声明可核查，不自动下载执行不明包。外部登录/采购/公开部署仍须原有授权。
4. 原生新安装无外部Agent运行时也可启动及完成完整任务；四后端以插件身份默认启用且真实状态可见，独立移除不损坏原生；Browser Use/电脑操控默认未安装，市场装用停卸各路径真实验证。
5. M建立插件默认矩阵、公共契约及迁移/包布局后按完整垂直包派工，L4；公共组合根/设置/发布由M统一接线，测试/试跑继续最低成本。完成前保持生产验收open，不拿目录/开关/编译通过代替安装运行链。
