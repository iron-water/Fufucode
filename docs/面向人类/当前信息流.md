下面按**当前 Fufucode + Pi 1.1.0 的代码接线**展开。每个编号框都有对应的子流程，子流程里再嵌套更小的流程。

贯穿示例：用户说 **“修复 calculator.py 的除零问题，运行测试，并说明修改。”** 使用人工确认模式。这个例子用于说明链路，未实际执行。

**① 总图：一轮对话经过哪些地方**

```mermaid
flowchart TB
    U["用户"]

    subgraph DESKTOP["本机：Fufucode"]
        direction TB
        subgraph GUI["Avalonia GUI"]
            A["② 打开项目、准备会话"]
            B["② 输入任务、点击发送"]
            E["⑤ 显示文字、工具进度与最终结果"]
            Q["④ 显示审批，接收用户选择"]
        end

        subgraph CORE["Fufucode Core"]
            C["管理会话、命令、运行状态"]
            R["Pi RPC：stdin / stdout JSONL"]
        end

        subgraph PI["受管 Node 进程：Pi 内核"]
            L["③ 组织上下文、调用模型、执行工具循环"]
            P["④ fufucode-bridge 审批扩展"]
            T["本地工具：read / edit / bash 等"]
        end

        F["项目文件、Shell 子进程"]
        J["⑥ Pi JSONL：对话与工具结果"]
        DB["⑥ 桌面数据库：项目、会话索引等"]
    end

    M["模型服务：网络 API"]

    U --> A --> B --> C
    C --> R --> L
    L <-->|模型请求与流式响应| M
    L -->|提出工具调用| P
    P <-->|审批请求与答复，经 RPC / Core| Q
    U <-->|查看并选择| Q
    P -->|获准执行| T
    T <-->|读写文件、执行命令| F
    T -->|工具结果| L
    L -->|协议事件，经 RPC / Core| E
    E --> U
    L --> J
    C --> DB
```

这里有两条不同的连接：**Fufucode ↔ Pi 是本机进程管道；Pi ↔ 模型服务是网络请求。** 模型提出工具调用，Pi 在本机执行，GUI 展示过程并承接审批。

            READY["查询状态、验证审批桥、读取历史<br/>新会话应用模型偏好"]

    end

        RPC["写入带请求 ID 的 prompt JSONL"]
        ACK{"Pi 接受了吗？"}

    START --> PATH --> CONF --> TRUST
    TRUST -->|否| ASK --> TRUST
    TRUST -->|是| PICK
    PICK -->|新建| NEW --> LOCK
    PICK -->|恢复| OLD --> LOCK
    LOCK --> SPAWN --> EXT --> PIPE --> READY --> ENABLE

**`prompt` 的成功响应只表示消息被接受、排队或由扩展处理。它不表示任务完成。** 事件订阅与读取已经建立，所以即使模型很快返回，也能接住输出。普通文字在运行中再次发送，当前适配器会走后续消息队列。

**③ 展开“Pi 执行循环”：AI 怎样真正完成任务**

```mermaid
flowchart TB
    IN["收到示例任务"]

    subgraph LOOP["C：Pi 内核负责的执行循环"]
        CTX["组织模型上下文<br/>系统指令、当前分支历史、用户消息、工具定义"]
        CALL["向配置的模型服务发起请求"]
        STREAM["接收流式文字、可用的思考块、工具调用参数"]
        KIND{"模型这一步要求什么？"}

        subgraph TOOL["C1：一次工具执行"]
            PROPOSE["模型提出工具名称与参数"]
            APPROVE["进入④工具策略与审批"]
            ALLOW{"允许执行？"}
            EXEC["Pi 执行工具"]
            RESULT["得到工具结果<br/>内容、退出状态或错误"]
            BLOCK["生成被策略阻止的工具结果"]
        end

        NEXT["把工具结果加入上下文"]
        ANSWER["模型给出本次回答<br/>message_end"]
        END["一次底层 agent run 结束<br/>agent_end"]
        MORE{"Pi 还会自动继续吗？<br/>重试、压缩恢复、插话或后续队列"}
        RECOVER["处理重试、压缩或待处理消息"]
        SETTLED["没有自动续跑工作<br/>agent_settled"]
    end

    UI["⑤ GUI 持续接收文字、状态和工具事件"]

    IN --> CTX --> CALL --> STREAM --> KIND
    STREAM -.-> UI
    KIND -->|工具调用| PROPOSE --> APPROVE --> ALLOW
    ALLOW -->|是| EXEC --> RESULT --> NEXT
    ALLOW -->|否| BLOCK --> NEXT
    NEXT --> CALL
    KIND -->|本次回答结束| ANSWER --> END --> MORE
    MORE -->|是| RECOVER --> CTX
    MORE -->|否| SETTLED
    EXEC -.->|工具进度| UI
    RESULT -.->|工具结果| UI
    SETTLED --> UI
```

示例中，这个循环可能是：

**读取 calculator.py → 读取测试 → 编辑代码 → 执行测试 → 根据失败输出继续修改 → 再测试 → 说明结果。**

这个顺序由模型结合实际结果决定。工具失败或用户拒绝，并不必然结束整轮任务；Pi 可以把失败结果交回模型，让模型调整方案。

**④ 再展开“工具审批”：GUI 怎样参与内核执行**

```mermaid
flowchart TB
    TC["Pi 即将执行工具<br/>触发 tool_call hook"]

    subgraph POLICY["D：fufucode-bridge 决策"]
        MODE["结合执行模式与工具策略"]
        DECIDE{"允许 / 拒绝 / 询问？"}
        PASS["直接放行"]
        DENY["返回 block:true"]
        
        subgraph ROUNDTRIP["D1：一次人工审批往返"]
            SNAP["保存待审批的工具参数快照"]
            REQUEST["ctx.ui.confirm<br/>Pi 发出 extension_ui_request"]
            CORE["Core 登记请求 ID、进程代次和超时"]
            GUI["GUI 显示非模态审批窗口<br/>主窗口仍可接收流式事件"]
            USER{"用户允许吗？"}
            RESPONSE["Core 校验请求仍有效<br/>写回 extension_ui_response"]
            VERIFY{"确认有效，参数复核通过？"}
            RECHECK["参数发生变化：重新询问并复核<br/>无法确认一致则阻止"]
        end
    end

    DO["返回③：执行工具"]
    ERR["返回③：向模型报告工具被阻止"]

    TC --> MODE --> DECIDE
    DECIDE -->|允许| PASS --> DO
    DECIDE -->|拒绝| DENY --> ERR
    DECIDE -->|询问| SNAP --> REQUEST --> CORE --> GUI --> USER
    USER -->|允许| RESPONSE --> VERIFY
    USER -->|拒绝、取消或超时| DENY
    VERIFY -->|通过| PASS
    VERIFY -->|参数变化| RECHECK
    RECHECK -->|复核通过| PASS
    RECHECK -->|复核失败| DENY
    VERIFY -->|请求失效或通信失败| DENY
```

当前四种模式会改变这个决策：

- **人工确认**：按工具策略决定放行、拒绝或询问。
- **自动审批**：自动允许未被策略禁止的内置 `write/edit`；Shell 与未知工具仍按策略处理。
- **完全访问**：审批桥放行所有工具。
- **规划模式**：只放行 `read/grep/find/ls`。

这些是应用审批策略，**不等于 Windows 系统沙箱**。扩展执行权限还需要结合扩展本身判断。

```mermaid

        TYPE{"记录类型？"}
        RESPONSE["命令响应<br/>按请求 ID 唤醒等待者"]

        ADAPTER["PiChatSessionAdapter<br/>协议事件 → SessionEvent"]
        THREAD["转到 Avalonia UI 线程"]
        WHAT{"事件内容？"}
        TEXT["文字 / 思考块增量<br/>更新已有消息"]
        TOOL["工具调用与执行结果<br/>更新工具块及状态"]
        STATUS["运行 / 压缩 / 重试 / 错误<br/>更新界面状态"]
        FINAL["消息终态<br/>校正最终内容与用量"]
        DONE["TurnSettled<br/>显示本轮完成、失败或中断"]
    end

    USER["用户边执行边看到变化"]

    PI --> PARSE --> TYPE
    TYPE -->|response| RESPONSE
    TYPE -->|event| EVENT --> STATE --> ADAPTER --> THREAD --> WHAT
    WHAT --> TEXT --> USER
    WHAT --> TOOL --> USER
    WHAT --> STATUS --> USER
    WHAT --> FINAL --> USER
    WHAT --> DONE --> USER
```

三个结束信号各有含义：

**`message_end`：一条消息结束。`agent_end`：一次底层运行结束。`agent_settled`：Pi 不会再自动继续这一轮。**

Fufucode 用最后一个信号结合错误与中断状态，判定本轮结果。“完成”表示本轮正常收尾；是否修复成功、测试是否通过，还要看工具结果。

    RUN --> META --> SQL
    JSONL --> CLOSE

**恢复历史，并不表示恢复原来的运行现场。** 当前链路会重新启动 Pi、读取已保存会话；它没有接入 Pi Durable 的执行状态恢复，也不会因此自动重放被打断的工具任务。

**⑦ 旁路：用户插话、停止，以及运行故障**

```mermaid
flowchart TB
    ACTIVE["③任务正在运行"]

    subgraph HUMAN["G：运行中的用户操作"]
        CHOICE{"用户做什么？"}
        FOLLOW["普通发送：followUp<br/>排入后续消息"]
        STEER["选择插入：steer<br/>交给 Pi 在调度点处理"]

        subgraph STOP["G1：停止流程"]
            CANCELUI["先取消待处理审批"]
            CLEAR["clear_queue<br/>取回尚未消费的消息"]
            ABORT["abort<br/>中止当前操作"]
            CONFIRM{"停止成功得到确认？"}
            STOPPED["标记中断<br/>未消费消息回到可恢复区"]
            UNCERTAIN["显示停止失败或未知状态<br/>不能宣称已经停止"]
        end
    end

    subgraph FAULT["G2：故障处理"]
        KIND{"故障在哪里？"}
        MODEL["模型服务错误<br/>Pi 可能重试；最终错误交回 GUI"]
        TOOL["工具错误 / 测试失败<br/>工具结果交回模型，可继续修正"]
        PROCESS["Pi 退出或协议连接损坏"]
        DISCONNECT["标记连接故障<br/>撤下待审批窗口，展示诊断"]
        RESUME["之后按⑥重新打开已保存会话"]
    end

    ACTIVE --> CHOICE
    CHOICE -->|继续发消息| FOLLOW -->|回到③| ACTIVE
    CHOICE -->|插入指令| STEER -->|回到③| ACTIVE
    CHOICE -->|停止| CANCELUI --> CLEAR --> ABORT --> CONFIRM
    CONFIRM -->|是| STOPPED
    CONFIRM -->|否| UNCERTAIN

    ACTIVE -->|发生故障| KIND
    KIND --> MODEL
    KIND --> TOOL -->|回到③| ACTIVE
    KIND --> PROCESS --> DISCONNECT --> RESUME
```

这组图的职责划分是：**Fufucode 管桌面交互、审批策略、展示与进程生命周期；Pi 管上下文、模型调用、工具循环和对话历史。** Codemode、MCP、tool-search 可以扩展③里的执行能力，但当前产品没有默认启用；Subagent 与 Durable 也没有接入这条主链路。
